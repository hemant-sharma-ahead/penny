Backup — "Next auto backup" caption on the Drive row (v1)

Scope: apps/mobile/src/features/backup/AutoBackupCard.tsx's expanded Drive panel — the tappable caption row that currently reads only "Backed up · {date}" (opens Backup History on tap). This adds a second line below it: when the next automatic backup is expected, computed from the same values the engine itself already uses (lastBackupAt + getBackupFrequencyDays() × 24h) — no new state, no new fields, purely a derived display value.

grounded in today's conversation Triggered by a real report: last Drive backup was manual, yesterday 9:35 PM, frequency 1 day — at 6 PM today that's correctly not due yet (~20h25m elapsed of the 24h window), which wasn't obvious from the card alone. Also handles the case actually described earlier in this thread: automatic backup only runs while the app is open (no background task exists) — so if the window elapses while the app isn't open, "next backup" needs to read as overdue, not silently show a stale past time.

Same "Backed up · …" line as today, plus one small line underneath — no layout shift elsewhere on the card.
Three states, one formula: next = lastBackupAt + getBackupFrequencyDays() × DAY_MS — computed the same way backupEngine.ts's own dueDaily already does, so the caption can never disagree with the actual gating logic.
  • Upcoming (next > now): Next backup · {formatDateTime(next)}, same tertiary grey as the line above it.
  • Overdue (next ≤ now — the window elapsed but nothing has run yet, e.g. the app wasn't open): Next backup · due now — runs the next time you open the app, in the warning color, so a real "why hasn't this happened" moment reads as informative rather than broken.
  • Auto-backup off: line is hidden entirely — nothing is scheduled, so there's nothing to show; the toggle above already communicates the off state.
Not shown if there's no backup yet (lastBackupAt is null) — caption stays exactly "Not backed up yet", same as today, since there's no baseline to compute a next run from.

Also applies to "This device": its own daily snapshot uses the identical due-in-24h check (backupEngine.ts's local branch, fixed 24h, not user-configurable) — same caption addition would fit there too.
