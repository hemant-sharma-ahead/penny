Notes / implementation shape

  • `ExpenseForm.tsx` gains a `goalPreset` prop (e.g. { goalId, goalName }): hides the Goal `ExtraCircle`/picker panel entirely (goal is fixed, not chosen), shows the small "Contributing to {name}" caption instead, restricts the type switch to Expense/Transfer only (no Income tab), defaults categoryId to cat-savings and description to "Contribution: {name}" (both still editable), and hides the IOU Lent/Borrowed section (not relevant once a goal is already the fixed context). Saving calls the existing goal-contribution save path (reconcileLinkedGoalTxn + a matching GoalContribution, origin manual) instead of the plain expense save — everything else (amount, date+time, account chips incl. the inline "+", paid via, tags, receipt, repeat) is the exact same code path as any other transaction.
  • `GoalContributionForm.tsx` is retired for new contributions. A tiny fallback (amount + date only, no styling changes needed) remains solely for editing pre-existing manual/no-transaction contributions from before this change — they have no linked `Expense` record for `ExpenseForm` to open, so there's genuinely nothing else to show for them. New contributions can never end up in this state again.
  • `GoalCard.tsx` drops `onQuickContribute` and its inline amount-entry state entirely; gains `onAddContribution(goal)` / `onLinkExisting(goal)`, wired in `GoalsTab.tsx` to the exact same `setContributionForm`/`setLinkingGoalId` calls `GoalDetailView`'s footer already uses — same handlers, two natural entry points (card for a quick add, Detail when you're already reviewing the ledger), not two different implementations of the same thing.
  • `LinkTransactionModal.tsx` — reviewed, already consistent (search + row list matching the rest of the app); no changes proposed there.
