Linking transactions to Goals

Five screens change. Grounded in how Cashew actually does this (researched — see below) and in Penny's existing IOU↔Expense two-way link, which already solves this exact shape of problem for a different feature.

Research: how Cashew does it

From Cashew's own FAQ: "When adding or editing a transaction, assign it to the goal by selecting the goal in the Add/Edit Transaction page." · "Assign any transaction to a goal when creating or editing it. You can contribute from any account." · "Transfer transactions can also be added to goals. Pair goals with transfers to reflect real money movements between funding and destination accounts." · "Goal progress is the sum of transactions assigned to the goal compared against its target amount." Cashew has no separate contribution ledger at all — a goal is just a live sum over tagged transactions (income, expense, and transfer all qualify), and there's no dedicated "all transactions for this goal" screen beyond the progress total itself.

Where Penny differs on purpose: Penny already has a two-way link pattern for IOU (core/iou/expenseLink.ts's reconcileExpenseLink/reconcileLinkedTxn, ExpenseForm.tsx's Lent/Borrowed toggle, EntryForm.tsx's "Record matching transaction" toggle, PersonLedgerView.tsx's per-person entry list) — and a real, currently-unused GoalContribution table already exists in the schema (defined, seeded for demo data, but never actually written to by any real user action on either platform — "Add contribution" today just bumps goal.currentAmount directly). This design finishes that table's job and mirrors IOU's exact shape rather than inventing something new — plus adds the "see everything for this goal" view Cashew itself doesn't have.

What each screen actually does, and the open questions

ScreenChange
ExpenseForm.tsxNew "Contribute to a goal" toggle + picker, mirroring the existing Lent/Borrowed section. Shown for expense/income/transfer (IOU's own section stays expense/income-only, unchanged). On save, resolves to a new pure reconcileGoalLink() in a new core/goals/goalLink.ts — same shape as reconcileExpenseLink().
useExpenses.tsNew seedGoalFromExpense (mirrors seedIouFromExpense) + goalLinkByTxn derived map (mirrors iouLinkByTxn), writing real GoalContribution records (finally using that dormant table) instead of leaving goal linkage as a UI-only concept.
GoalCard.tsx / GoalsTab.tsxCard becomes tappable → opens Goal Detail. Linked-transaction count badge added. Existing inline "Add contribution" quick-action kept as-is for fast logging without opening the detail view.
New: GoalDetailView.tsxCentred Modal, same family as PersonLedgerView.tsx — progress ring, full linked-transaction list (tap → opens that transaction in the real Expense form), footer: "Link existing" (retroactively tag an already-recorded transaction) + "Add contribution" (primary).
GoalContribution (add/edit)Gains a "Record matching transaction" toggle (mirrors EntryForm.tsx's, on by default) + account picker. On: creates a real Expense (category cat-savings, "Savings Transfer") via a new reconcileLinkedGoalTxn() — mirrors reconcileLinkedTxn() exactly. Off: behaves like today (a note-only bump to currentAmount, no transaction).
  • Goals screen itself doesn't need a structural overhaul — just cards → tappable, plus the one new Detail modal. No new navigation route/pushed screen needed, same as IOU never needed one for PersonLedgerView.
  • A transaction could theoretically be linked to both an IOU entry and a Goal at once (e.g. lending money that's also earmarked toward a goal) — this design doesn't forbid it, since the two toggles are independent, but it's an edge case worth a explicit yes/no from you rather than assuming.
Two things I'd rather you decide than guess:
  • Contribution transactions — Expense or Transfer? Cashew treats a goal contribution as a Transfer when you track a separate destination account for it, or an Expense otherwise. Frame 5 above defaults to Expense (simpler, always available even with one account) — but if most of your goals map to a real dedicated savings account, Transfer (source account → destination account) would be more accurate. Happy to support both and let the toggle pick, but wanted your steer on the default.
  • Should linking to a goal exclude that transaction from spending analytics, the same way IOU-linked transactions already are (iouLinkedTxnIds — "lending isn't daily-living consumption")? A goal contribution arguably isn't routine spending either.
