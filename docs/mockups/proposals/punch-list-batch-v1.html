① Transactions

Month scrub bar — always show the year (13b) + dim empty months (15)

Scope: apps/mobile/src/features/expenses/transactions/MonthScrubBar.tsx. Chip label logic: packages/core/src/lib/date.ts's monthChipLabel() (13b). Empty-month detection (15) is new — computed alongside TransactionsSlice.tsx's existing scrubMonths walk (ascending, earliestMonth → current month), a cheap same-pass boolean map, no new query.

reverses a prior decision Item 13b intentionally reverses docs/plans/real-device-testing-pass.md item 43 v5, which chose to omit the year for the current calendar year specifically to keep chips short ("Aug" vs "Jul 2025"). Real use surfaced the cost: the strip spans a full year+ of history, so a chip's format silently changes the moment a year boundary is crossed while scrolling — "Jan" sits right next to "Dec 2025" today, which reads as inconsistent rather than economical. Always showing the year (below) is a one-line change to monthChipLabel() and costs a few extra characters per chip; flagging the reversal explicitly rather than silently re-deciding it.

③ Accounts

Account tile — verified caption + unverified-tail state (4), per-tile Import History (8), icon consistency (9)

Scope: apps/mobile/src/features/accounts/AccountList.tsx (tiles), AccountsPage.tsx (header icon row). verifiedThroughDate is already computed (AccountDetailModal.tsx, from Account.coveredStatementRanges) but never surfaced on the list tile itself today — only the negative needsAttention triangle is.

design call — placement The verified caption/tail-flag are placed inside the kebab-revealed action row (left of the icon buttons), not as a third always-visible line on the resting row. Rationale: the resting row is already at its "uncluttered" ceiling (name + default pill + warning triangle + balance + net-worth caption); the reveal row already exists as a secondary information/action surface and currently wastes its own left half on empty space (icons are justify-end). This reuses that space instead of adding a new permanently-visible line to every tile. Flagging since the item description could also be read as "always visible" — happy to move it up if that reading was intended.
both nav paths kept Per item 8's own scope: the global header "Import History" icon is not removed — cross-account browsing (e.g. "which account did I import last?") is still a distinct job from "show me this one account's history," so both entry points coexist, same as this repo's own note that duplicated capability (not duplicated entry points to the same job) is what needs consolidating.
neutral, not primary Item 9's three promoted icons (Merchant recognition / Cash-withdrawal codes / Import History) get a secondary/neutral boxed style (tinted surface + border), deliberately not primary blue — that colour stays reserved for "Add," the screen's one true primary action, so it doesn't get diluted by three other buttons matching it.

④ Settings

3-day default-to-Open with a Settings-only countdown banner (item 12)

Scope: apps/mobile/src/features/settings/SettingsPage.tsx's empty "Frequent" card first-row slot (the exact spot the pre-2026-08-18 default-mode picker used to occupy), a brand-new persisted preference (pattern per SettingsContext.tsx's existing AsyncStorage-key convention), and a change to PrivacyContext.tsx's AppState background-revert effect to suppress itself while armed. Nothing like this exists elsewhere in the app — it lives only in this one card.

design call — row → banner shape shift The never-used state renders as an ordinary Row (icon + label + sub + chevron) — it should look like "a settings option you haven't turned on," per the item's own instruction, not an empty gap. Once armed, that same first slot becomes a real Banner-shaped element (title + sub + a countdown pill + an inline "Switch back to Safe" action) rather than staying a plain chevron row — the countdown and the manual-revert action both need more surface than a one-line row's trailing slot can hold. Flagging the shape change since it's a judgment call, not spelled out in the item.
design call — urgency colour The icon/identity colour stays Open-mode red in both armed states (it's always "you're in Open mode by default," regardless of how much time is left) — but the countdown pill itself shifts from a neutral/green "days left" tint to an amber "hours left" tint, borrowing the ordinary running-out-of-time convention without overloading the red Open-mode identity colour with a second, conflicting meaning.
accepted trade-off, restated While armed, foregrounding the app after backgrounding goes straight back to Open with no PIN — an unattended unlocked phone stays in Open mode for the remainder of the window. This is the explicitly accepted trade-off from the item spec (the whole point is fixing app-switching PIN friction), not an oversight — restated here so it isn't lost between the mockup and implementation.
