Transactions list — icon clarity + compact date header

Two open questions from the last round. Dot-centering, the responsive category grid, and the goal filter icon were all clear bug/consistency fixes and are already built — these two are genuine design calls, so here's a mockup for both before touching code.

1 — Import/Export icons
Both current icons are a "file" glyph with a tiny arrow — nearly identical silhouettes at 14px, which is exactly why they're hard to tell apart at a glance. Swapping to plain up/down arrows gives two genuinely different shapes instead of one shape with a small detail changed.

Recommendation: Option A (tightened padding). It gets you most of the space back (roughly half the header's current height) with zero risk to readability or to `FlashList`'s cell-recycling setup — headers and transaction rows stay two cleanly separate recyclable types, just a smaller one. Option B (inline-on-rail) saves a bit more space and looks slick in isolation, but it means the first transaction of every day needs a taller top margin to make room for the date label above it — inconsistent row heights across a day boundary, and a fussier one-off case for `FlashList`'s recycling (that row can no longer be visually identical to every other transaction row). Not worth the extra space for the added complexity, but happy to build it if you'd rather have the tightest possible list.

What's already built (no mockup needed, shipped directly)

  • Dot/rail centering — `TransactionsTab.tsx`'s dot used `top: '50%'` + `marginTop: -5` on an absolutely-positioned sibling, which isn't reliable on-device under this project's NativeWind/interop setup once row heights started varying (same class of bug `MainTabs.tsx`'s `HeaderCenter` hit once). Replaced with a flex column (two equal-flex rail segments around a fixed-size dot) — pure flexbox distribution, no percentage-of-parent math.
  • Responsive Account/Category grid — tiles measure the modal's actual available width (`onLayout`) and compute 4–6 columns to fit it, instead of a fixed 64px tile that left unused space on wider screens.
  • Goal filter icon — each Goal chip in the Filter popup now shows its resolved icon (`resolveGoalIcon()`, the same keyword-inference built for the Goal card), tinted by its risk colour — same treatment Event chips already get with their colour dot.
