Backup — Drive "foreign blob" banner: add "Overwrite Drive" (v1)

Scope: apps/mobile/src/features/backup/AutoBackupCard.tsx's status === 'foreign_blob' banner. Today it renders only "Restore with my passphrase". This adds a second, destructive option — "Overwrite Drive with this device's data instead" — gated behind the same ConfirmDialog shape already used on this screen for "Erase all data" (BackupPage.tsx). No other part of the card changes.

cross-platform check apps/web-react/src/features/backup/AutoBackupCard.tsx has no foreign_blob handling at all — that whole banner (including the existing single button) was added mobile-only on 2026-08-18 per real-device testing feedback and never existed on web. This is a pre-existing platform disagreement, not one this change introduces — and since apps/web-react is frozen (no further changes, historical reference only), nothing needs mirroring there. Flagging per the parity-check step so it's a documented finding rather than a silent gap.

Solid danger variant (same red as "Erase all data" below on this screen) so it reads as the more destructive of the two — vs. the existing outlined secondary restore button.
Copy logic (inverse of restore): "Restore with my passphrase" brings the old Drive data back onto this device. "Overwrite Drive with this device's data instead" abandons the old Drive data and starts writing this device's data to Drive going forward — real scenario: a reinstalled/new device where the user doesn't want the old backup back and today has no way to tell the app that.

Component reuse, not a new pattern: both buttons are the existing Button component (variant="secondary" unchanged, new one variant="danger") inside the same View className="gap-2" block; the dialog is the exact same ConfirmDialog used for "Erase all data" — title / message / confirmLabel="Yes, overwrite Drive" / confirmVariant="danger" — no new dialog shape.

Out of scope, left as-is: the footer's "Back up now" button stays visible/enabled in this state exactly as it does today — not proposing a change to it here.
