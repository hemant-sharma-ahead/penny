Recommendation

Build this as the final design — it's a direct synthesis of what you approved across three rounds, not a new direction: v1's accordion mechanic (now 2 sections), v2's dense Accounts list and Merged Transfer Diagram, v3's category tiles reduced to inline stats and small pill actions. No open questions remain that need a design decision; implementation notes below.

  • On web this is one route: two <details>-like accordion sections in a single scroll, sticky progress header pinned via position: sticky, driven by the same readyRows/rejectedRows/categoryResolutions/accountResolutions shape the current apps/web-react/src/features/import/ core already exposes.
  • The "N rows need fixing" collapsible maps directly to rejectedRows (rows that never parsed) — keep it visually distinct (amber, not the neutral card style) from category tiles so a user never confuses "structurally broken" with "category undecided."
  • Pill actions: 4 per category tile at this width is workable at 10.5px/compact padding as shown, but test with a longer target-category name (e.g. "Subscriptions & Memberships") before committing — if it wraps to 2 rows often, collapse to a primary pill + a single "More" overflow instead.

Verdict: ship this. Recommend a quick side-by-side against a 12+ category, 5+ account real file before final sign-off, since density choices (pill wrapping, accordion scroll length) read differently past this round's illustrative sample size.

Cross-platform note: unchanged from prior rounds — apps/mobile/src/features/import/ImportPage.tsx has no Resolve/Preview parity with the current apps/web-react import core at all yet (no accordion, no accounts/preview split, stale useImport() shape). Whichever round is final, mobile needs a full port of this accordion + dense-preview design — not a style pass — and this should be tracked as its own follow-up in docs/MOBILE_PARITY.md once approved, per the project's cross-platform-by-default rule.
