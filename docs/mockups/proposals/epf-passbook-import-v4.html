Recommendation: A + the untracked-CTA addition

Go with A — a card-level "Import passbook PDF" action, placed once, above Employment, that owns the whole "parse → figure out which employer → create or extend it → reconcile its transactions" flow — this matches what a PDF actually contains (doc §4: one employer's header block + a full FY of transactions), so it shouldn't be scoped to only one of the card's three existing sub-flows. B was considered and rejected: it reads naturally for a first-time import (new employer appears in Employment) but has no good story for the equally common case of importing a missing FY for an employer already tracked — that action has nothing to do with Employment at all. Also add the untracked-CTA shortcut so a brand-new EPF holding can be created directly from a first PDF instead of manual entry — the "Track EPF" flow (0.1) currently forces typing UAN/company/basic salary by hand even though a passbook already has all of it.

Consistency note — tappable rows preserved

Confirmed in RetirementSheets.tsx (screen 0.11's month rows, selectedMonth state): tapping a transaction row opens a breakdown popup (employee / employer-EPF / EPS split, plus pro-rata days if applicable). Nothing in this proposal removes that — it stays exactly as-is on the real Transactions list. It's also extended forward into the new review screens (§2 Direction C, §5.2 above): a "New" row awaiting import can be tapped the same way to see its employee/employer/EPS split before confirming, not just after import.

6Interest transactions — show the rate + calculation
Your ask: since the rate can differ by FY, show which rate applied — and if possible, the calculation itself. No schema change needed: the rate is already derivable on demand from the FY via lookupRateForMonth(), and the month-by-month trace is already computed internally by calculateEpfInterestForYear() — it just isn't returned today. Extending it to optionally return that trace, and making interest rows tappable the same way contribution rows already are, gets this without storing anything new. Works identically whether the entry was typed manually, calculated via §4's assistant, or came from an import — the rate/trace is always recomputed fresh from the FY + logged contributions, never stored stale.

Workbook contents design note, not a screen
What "Export" produces — a real spreadsheet, described here rather than pixel-mocked.
Penny_EPF_Statement.xlsx
  1. Summary — corpus, per-employer totals, retirement projection, generated-on date
  2. Employers — one row per employer: name, dates, basic salary, UAN/member ID if known
  3. Transactions — every contribution/interest/transfer/withdrawal, all employers combined, with a rate-used column on interest rows
  4. Interest History — one row per FY: rate applied, employee/employer interest credited
  5. Salary Hikes — one row per hike event per employer
Re-import reads sheets 2–5 back into the same reconciliation engine §2 already uses — no new matching logic, just a new reader parallel to epfPassbookParser.ts.

Cross-platform note

EPF passbook import is a brand-new capability with no prior implementation on either platform, and apps/web-react's equivalent files are currently at parity with mobile's (same entry points, same PPF banner pattern, same modal structure). Per this repo's default rule a new capability would normally be mirrored — but apps/web-react is frozen as of 2026-07-31, so this proposal is scoped to apps/mobile only unless told otherwise.

What changed from v1 → v2 → v3

v2: (1) Rebuilt entirely in the real light theme (packages/core/src/theme/tokens.ts's light palette + privacyModeColors.ts's #e4eeff page background) instead of an invented dark theme. (2) Added §0 — all 11 real current screens, reproduced from the app itself. (3) Corrected §1's entry point: the real card has three existing manual entry points (Employment add, salary hike, transaction add) plus a separate Edit-EPF modal and an untracked-CTA state — v1 only ever looked at the transactions-list sheet in isolation and missed that an import can create a new employer, not just add transactions. (4) Layout is now a horizontally-scrolling strip per section instead of wrapping, per request. v3: (5) Added §5 — multi-file batch import (batch summary → sequential per-file review reusing §2's Direction C unchanged → one combined done screen), resolving the "multiple statements at once" question. (6) Explicitly confirmed the existing tappable-row breakdown behavior is preserved and extended into the new review screens. v4: (7) Added §6 — interest transactions now show the FY's declared rate and are tappable for a month-by-month calculation breakdown, computed on demand (no new schema field — see §6's note). (8) Added §7 — an "Export statement" action producing one combined Excel workbook across all employers/years, and confirmed the same "Import" action re-reads that exact file back in (auto-detected, same reconciliation screen, no second entry point).
