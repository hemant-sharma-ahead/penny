Portfolio — where should "refresh" live?

Three genuinely different directions, not variations on one idea. All three still dispatch to whichever of Stocks/MF prices, IPO data, or News headlines is relevant for the active sub-tab — only the trigger's position/form changes.

A — Pull-to-refresh gesture, no button
The standard mobile pattern for "this list might be stale" — pull down on the holdings/IPO/news list itself, a spinner appears, releases when done. No persistent button anywhere, ever — the header goes back to just the totals, nothing else.

Trade-offs

  • A — Pull-to-refresh: cleanest header, zero persistent chrome for this. Downside: it's discoverable only if the user already knows the gesture (common on iOS/Android, but not universal), and there's no visible "last updated" freshness signal unless you add one separately. Needs `RefreshControl` wired into each of the three scroll containers (holdings `ScrollView`, IPO's `FlatList`, News' `FlashList`) — real but small work, no new component.
  • B — Icon in the sub-tab row: stays contextual (right next to Stocks/MF/IPO/News) and out of the header. Downside: it's a 5th element competing for space in a row that already holds 4 tabs — fine on this screen width, could get tight if a sub-tab label ever grows.
  • C — "Last updated" row: most explicit about freshness, closest to what IPO's screen already showed on its own before this consolidation. Downside: costs a full row of vertical space above the content, on every sub-tab, all the time — the one most likely to feel like "one more bar" rather than decluttering.
Recommendation: A, pull-to-refresh — it's the idiomatic mobile pattern for exactly this ("this data might be stale, let me ask for fresh"), and it fully removes the button from the header rather than just relocating it, which is what actually prompted this ask. Freshness ("last updated") could still be added later as a small subtitle if it turns out to be missed, but I'd ship without it first rather than assume it's needed.
