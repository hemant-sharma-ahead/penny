CSV Import — full-screen transaction browser for high-volume category groups (v2)

Grounded in TileRowList.tsx, CategoryTile.tsx, ImportCategorizeModal.tsx and the already-shipped MonthScrubBar.tsx (approved via fourth-batch-redesigns-v5.html §4). Two real on-device findings this fixes: (1) a category-resolution group with hundreds/thousands of rows is unworkable to review in TileRowList's 260px scroll box + "Show 60 more" pagination-in-place; (2) importCounterpartySplit.ts's per-counterparty explosion of MoneyView "A/c to A/c" rows is a workaround for problem (1), not a real fix — once a group of hundreds is genuinely browsable, the split can be removed and the group can stay ONE row.

Changed since v1 (direct user feedback) — three localized corrections, §1 untouched:
  1. §2's tile no longer replaces the inline preview. The tile keeps rendering its real, unchanged TileRowList inline list (select-all row + 260px scroll box + "Show N more") exactly as it does today. "See all N →" is now an ADDITIONAL affordance below that list, not a replacement for it.
  2. "See all N →" is now a plain text link, reusing TileRowList's own real loadmorebtn styling verbatim (small, coloured text, no fill/border) — the heavy filled/bordered button from v1 is gone.
  3. Inside the popup, "Select all"/"Clear" now scope to whatever the month-scrub-bar has active — a specific month if one's picked, the whole group if "All" is active — reversing v1's judgment call #2 outright. Demonstrated live in §2 below, not just described.

2New — "See all" opens a full-screen browser
One tile per source again (counterparty split removed — see the callout below). The tile's body is unchanged from today — the real TileRowList inline preview (select-all row, 260px scroll box, "Show N more") still renders exactly as it does now. Once a tile's row count exceeds 60, a plain text link — "See all N transactions →", styled identically to "Show N more" — appears BELOW that inline list as one more way to reach the same rows, in a real interactive popup: month-scrub-bar narrowing (exact visual/behavior of the already-shipped MonthScrubBar.tsx), a running "N of M selected" count, per-row checkboxes, and the same real "Categorize N selected ›" footer.
Judgment call — counterparty split removed. importCounterpartySplit.ts exists only because a group of hundreds/thousands was unbrowsable as one tile. With this popup, that's no longer true — "A/c to A/c" ships as ONE tile again, and each row inside the popup carries its own small counterparty chip (still visible, still traceable to a Person match) instead of being pre-split into separate top-level rows. This mockup renders that removal but doesn't implement it — confirm before any useImport.ts/importTransactionsGrouping.ts code change.
Corrected from v1 — "Select all" inside the popup now scopes to the active month filter, not the whole group. Narrow to a specific month via the scrub bar, then "Select all" only checks/unchecks that month's rows — other months' selections are left exactly as they were. Switch to "All" and the same control covers the entire group again, same as before. Deliberately labelled "Select all" / "Clear" here — not "Select all" / "Unselect all" — so it never gets mistaken for the tile's own inline select-all row below (which stays whole-group, unscoped, matching TileRowList.tsx exactly, since that control has no concept of a month filter). Try it: open a popup, pick a month, tap "Select all" (only that month's rows check, the top "N of M" count rises by just that month's size), pick a different month, tap "Select all" again (the first month's checks are still there — counts compound), then tap "Clear" on the currently active month (only it unchecks) and switch to "All" (still covers everything, as before).
Judgment call — "All" still uses the existing 60-row cap + "Show N more", just full-screen now. Per docs/ARCHITECTURE.md's rule against an unbounded .map() over bulk data, "All" was never going to render all 1,639 rows in one shot even with the room a popup gives it — the cap just matters far less now that a month chip can jump straight to a specific slice instead of clicking "show more" repeatedly.
Cross-platform finding — the two platforms already disagree here, and this doesn't fix that. apps/web-react's own CategoryTile.tsx has no cap/pagination logic at all — it hard-slices to rows.slice(0, 8) with no way to see the remaining rows, ever. That's a worse gap than mobile's 60-row cap even had. Per CLAUDE.md, apps/web-react is frozen (historical reference only) — this mockup and any resulting implementation is mobile-only by policy, not because the platforms agree; flagging it since it's a real, pre-existing disagreement, not a new one this change creates.

Recommendation: ship the "See all" popup as designed here, and remove the counterparty-name split as part of the same change (not a follow-up) — the split's only reason to exist goes away the moment this popup ships, and keeping both would leave two ways to browse the same kind of large group.
  • Threshold matches today's exactly (60 rows) — a tile with ≤60 rows keeps rendering the plain inline list exactly as it does now, with no "See all" link at all; nothing changes for the common case.
  • The inline list itself is never replaced — "See all" is purely additive, so a user who's happy scrolling/paginating in place loses nothing.
  • The popup reuses three things verbatim rather than inventing anything: the centred Modal primitive (near-full-height via a scrollable body, not a bottom sheet), MonthScrubBar.tsx's exact chip/pinned-All/calendar-icon pattern, and ImportCategorizeModal unchanged (opened by the same "Categorize N selected ›" button, not redesigned).
  • Per-row visual is upgraded from TileRowList's plain two-line text row to the real TransactionsTab.tsx row convention (tinted category-color icon rail + amount/account) — a small, deliberate improvement now that there's room for it, not required by the "See all" mechanic itself.
  • New in v2: the popup's "Select all"/"Clear" scopes to the active month filter (or the whole group under "All") — reversing v1's opposite judgment call after explicit feedback. The tile's own inline select-all row is intentionally left whole-group/unscoped, matching TileRowList.tsx exactly, since it has no month concept to scope to.
