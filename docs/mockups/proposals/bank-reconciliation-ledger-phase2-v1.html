What's genuinely new here: the two action sheets above (built from the existing Modal + row-of-Buttons pattern, same visual language as PossibleMatchPickerModal's own bottom actions) and the unmatch confirm (ConfirmDialog, unchanged component). Picking "This isn't the right match" or "Pick the matching transaction" both hand off to PossibleMatchPickerModal exactly as it already exists today — no changes to that modal at all. "Add as a new transaction" hands off to ExpenseForm with a statementPreset, the same path bucket 3's "add as new" already uses live during import.

Design call worth flagging: Unmatch is a direct, one-step action (not funneled through the picker's own "no match" option) — tapping it immediately shows the confirm above, no extra screen. The unmatched statement line reappears as an ordinary skipped-unresolved row afterward, with the exact same resolve sheet available on it — no new row state, no lost data.
