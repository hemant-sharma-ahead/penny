The header's background now matches the body background exactly — no border, no seam — so it reads as part of the screen, not a fixed bar sitting on top of it.

Subscreens fully replace their own back+title row with this header — avatar swaps for a back-chevron. What actually changes in code

Header ownership stays exactly where it is — MainTabs.tsx still owns one persistent header row above Tab.Navigator. What moves: (1) its background becomes the same modeColors.bg the screen content already uses, instead of modeColors.headerBg with a 2px accent border underneath; (2) a new center slot renders either ContextSwitcher (Home tab root only) or a plain title string (every other tab root and every pushed screen); (3) the left slot becomes a BackButton-equivalent instead of the avatar whenever a pushed screen is active, the same "is this the deepest screen or not" check PageHeader's callers already make today by passing leading={'<'}BackButton /{'>'} or not.

Removed: the floating pill (ContextSwitcher's variant="floating") from HomePage.tsx — folded into the header instead. PageHeader's own title row goes away on every pushed screen inside HomeStack/ExpensesStack (its actions/children slots, where used, stay as a secondary content row below the header, they just lose their own title line). Chip's hand-rolled title block is replaced by the shared header too.

Recommendation: this direction, as drawn. It resolves the actual complaint (double headers, wasted vertical space, a floating pill that felt bolted-on) without inventing a new interaction — every screen keeps a single, predictable, always-in-the-same-place header, it just finally shows the one thing that actually matters per screen (where you are) instead of two competing signals.
