Accounts list — round 2: 7 genuinely different concepts

Round 1 (account-list-redesign-v1.html) offered three variations on one idea (a full-bleed gradient card, tightened three ways) and was rightly rejected as too similar. Direct feedback this round, verbatim: "What if we could have rounded square shaped cards and this way we can fit 2 in a row. And please use the exact bank icons like their own colors... Let's drop the gradient colors as it does not go with light and dark themes." Every option below is zero-gradient — flat semantic-token surfaces, or at most a flat/low-opacity tint layer, never a linear-gradient — and every HDFC/ICICI/Axis logo renders in its real, verified brand color (BankLogo.tsx's BANK_LOGOS: HDFC #004C8F, ICICI #B02A30, Axis #97144D) exactly as the component really draws it — never forced monochrome. SBI Savings and IndusInd Credit Card render the honest generic fallback (no logo sourced yet for those two presets), same as production. Same 6 accounts throughout every option for a fair comparison.

Update (this round): the real per-account action row was missing from all 7 options — now added everywhere, plus a correction to how it actually behaves. Ground truth from apps/mobile/src/features/accounts/AccountList.tsx: the bottom action row is Import statement (ti-upload, only when STATEMENT_IMPORTABLE — bank/credit_card), Reconcile balance (ti-scale, only when RECONCILABLE — cash/wallet, not bank/credit_card as this round's brief assumed), Edit (always), and Delete (always, pushed to the far right via ml-auto with a danger-tinted background, separated from the rest). Since AccountType is exactly 'cash' | 'bank' | 'credit_card' | 'wallet' and these two sets partition it with no overlap, every account gets exactly 3 buttons, never 2 and never 4 — (Import or Reconcile) + Edit + Delete. In this mockup's 6-account set that's Import+Edit+Delete for the 5 bank/credit-card accounts (HDFC, ICICI, Axis, SBI, IndusInd CC) and Reconcile+Edit+Delete for the one cash account (Cash Wallet) — there's no second cash/wallet account in this set to show a 4th/alternate case.

12-column grid, rounded-square tiles

Pick this when the app should keep "each account has its own identity" without a gradient or a jarring saturated fill — a flat bg-surface card with a low-opacity flat wash of the bank's real brand color layered on top (never a gradient — two flat layers stacked). 6Hybrid: pinned carousel + plain list
Pick this only if a real "primary accounts" concept is worth adding to the data model — a swipeable strip surfaces 2-4 accounts the user checks daily, everything else lives in a plain list below. Action row: deliberately not added to the pinned carousel cards — a horizontally-swiping strip of "check balance at a glance" cards is exactly the card-carousel pattern that defers detailed actions to a tap-through (opening the same account detail/edit surface every other option's row-tap already opens), and 132px-wide cards genuinely don't have room for 3 real buttons without either shrinking them past comfortable tap size or crowding the balance. Cross-platform status

apps/web-react's own AccountList.tsx is frozen (2026-07-31) and was never given real bank logos or a transaction count at all — it's a plain IconBadge (generic icon + the account's own color field, always the type default) + name + type-label + balance row inside a ListContainer, no chevron, no drill-down modal. Structurally this is closest to Option 2 (dense single-column, no card chrome) or Option 7 (single-line-per-account, balance right-aligned) — but plainer than either, since it has no logo-color treatment and no tx count. The two platforms already disagree today on this screen (same finding recorded in v1); that's expected and accepted — web is a historical reference only. This redesign is mobile-only; no web-react mirroring is proposed.
