Recommendation: Option 2. Safe-to-spend is a number people check almost every time they open Expenses to decide whether they can afford something — it shouldn't cost an extra tap (ruling out Option 3). Vacation mode is rare and short-lived, so it doesn't deserve permanent real estate next to the total every single day — better as a banner that only exists while it's true, not a pill that's either shown-and-crowding or a placeholder gap when there's no trip on. Events/Import/Export are all low-frequency actions (you don't reach for them daily) so folding them into one "⋯" is a clean, safe win in every option — no reason not to take it regardless of which stat layout wins.

Notes

  • Overflow menu (all 3 options): tapping "⋯" opens a small centred `Modal` (per `docs/DESIGN_GUIDELINES.md`'s "centered modals, never bottom sheets" rule) with 3 rows — Manage events (badge dot if any active), Import expenses, Export expenses — each triggering exactly what the 3 icons already do today. Same capability, one entry point instead of three always-visible icons.
  • Vacation banner (Option 2): conditionally rendered only when `immersiveEvent` exists — on every other month (the overwhelming majority), this row doesn't render at all, so nothing is lost, no placeholder gap either.
  • All three keep ExpensesHeader.tsx's existing data (`filteredTotal`, `safeToSpend`, `immersiveEvent`, the 3 action handlers) — this is a presentation-only change, no new state or props needed beyond a `showOverflow`/`bannerExpanded` local toggle.
