"Add a parser" redesign — concise form + bulk tester

Real usage found this screen sprawling, missing bulk-message testing, showing field-chip labels that don't match the regex's actual capture-group names, and silently going stale after fixing a broken regex (retriggers only on some field edits, not others). Three layout options below fix all four; pick one to build.

What's actually wrong Option A — Compact form + bulk tester (recommended) Option B — Split pane, form + live tester side by side Option C — 2-step: Define → Test
What's actually wrong today
1. Sprawling, low-density layout — huge all-caps labels with wide letter-spacing, "New bank ID" and "Sender ID patterns" stacked full-width instead of side by side, a redundant "TEST AGAINST" sub-header — the whole form runs several screens tall for ~8 actual fields.

2. Field-chip names don't match the regex you just wrote — the pattern textarea's placeholder and label both say acctLast4/cardLast4, but the live-match preview shows acct/card. Same underlying value, different label — confusing when you're checking whether your named group actually captured.

3. No way to test more than one message — "Test against" is exactly one Sender + one Body. A real new-template session usually starts with 3-10 real messages of the same wording variant (or the same bank under 2 different sender shortcodes) — today that means re-pasting one at a time.

4. Silently stale after a fix — this one's a real bug, not just a UX complaint: the "New bank ID" and "Sender ID patterns" fields update their state but never re-trigger the live match check. Fix your regex, and the preview doesn't refresh until you also touch Sender or Body again — it looks like the fix didn't work.
ACompact form + bulk testerRECOMMENDED
Tightens the form to a dense 2-3 column grid, puts New bank ID + Sender patterns side by side, replaces the single Sender/Body pair with the exact same paste box + --- block format already used in "Test your own" (one convention, not two), and adds an explicit ▸ Test button — no more silent auto-retry, and no more per-field inconsistency in what re-triggers it.
Results render as a compact one-line-per-message list (not full trace — there's only one candidate template here) — click a line to expand into highlighted text + field chips, same interaction already established in "Test your own"'s table.

C2-step: Define → Test
Splits the same fields across two explicit steps instead of one long scroll or a side-by-side split — "Define" holds just the template-authoring fields, "Test" holds the bulk paste box + results. A small persistent strip at the top always shows the current regex pattern, so you're never guessing what you're testing while on the Test step.
Trade-off: the extra click between steps is friction a single scrolling form doesn't have, and regex iteration (change pattern → immediately see if it matches) is the most common loop here — bouncing between two steps for that loop is worse than Option A's single view. Included for completeness, not the recommendation.

Decision: Option B, per feedback — the split-pane field sizing reads better than Option A's single dense column, now with Option A's color-coded highlighting/field-chip naming folded in (the .smstext mark-highlighting and exact capture-group-name chips are shared rendering, not layout-specific — Option B gets the identical treatment, not a lesser version).

Summary of what changes (Option B)

  • Layout: two panes side by side inside the main content area — left = template-authoring fields (Bank/Type, New-bank-ID/Date-format, Sender ID patterns, Regex pattern), right = the bulk tester (paste box, ▸ Test button, results list). Tighter label typography throughout (no more full uppercase + wide letter-spacing eating space).
  • Field-chip naming fix (real bug, applies everywhere fieldChips() is used — Known templates too, not just here): chips read the exact capture-group name from the regex (acctLast4, cardLast4, counterparty, ref, balance, dateStr, amount) instead of a shortened label (acct/card) that doesn't match what you just typed.
  • Color-coded highlighting, same as everywhere else in the tool: the right pane's expanded result shows the full .smstext block with color-coded <mark> spans (green=amount, blue=account/card, pink=counterparty, amber=ref/balance/date) — identical shared rendering to Known templates and Test your own, not a stripped-down variant for this screen.
  • Bulk tester: the right pane's "Test against" is the same paste box + ----block format as "Test your own" (splitIntoBlocks(), already implemented — reused, not reinvented), tested against the single draft template, rendered as a compact one-line-per-message list with click-to-expand (highlighted text + field chips), not the full per-template trace (there's only one candidate here).
  • Explicit ▸ Test button (real bug fix): replaces continuous auto-retest on every keystroke. Also fixes the actual reported bug — New-bank-ID and Sender-ID-pattern edits currently update state but never re-trigger a re-test, so fixing a regex and only touching those two fields left the preview looking stale. A single explicit action re-tests off the current full form state every time, regardless of which field was last touched.
