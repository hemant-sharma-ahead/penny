What changes in code

`PortfolioPage.tsx`: `activeTab` grows from 'holdings' | 'ipo' to a 5-way asset-class union ('equity' | 'fixed_income' | 'precious_metals' | 'retirement' | 'real_assets'); the existing 6-item HOLDINGS_SUBTABS config splits into a 4-item EQUITY_SUBTABS (stocks/mf/ipo/news) rendered only when Equity is active, while Fixed Income/Precious Metals/Retirement/Real Assets each become their own top-level tab rendering the same FixedIncomeSection/PreciousMetalsSection/ RetirementSection/RealAssetsSection components unchanged. IpoTab and the News screen's content (NewsPage.tsx's feed/filter logic) get pulled in as sub-tab content instead of standalone screens — their virtualized lists stay virtualized, just re-parented. Home loses its News tile; ToolsGrid.tsx (or wherever it lives) needs that entry removed. Settings' "Modules" section may need a look afterward too, since visibility toggles keyed to the old Holdings/IPO/News structure won't map cleanly to the new one.

Recommendation: this direction, as drawn — it's a faithful, minimal-risk re-parenting (every section component is reused as-is) that fixes the real complaint (Stocks/MF buried among 6 equal-weight pills) without inventing new visual language: the sub-tab strip reuses the same underline style Portfolio's main tabs already have, just recolored to signal "one level in."
Still worth deciding:
  • Does News's own source/tone/holding filter row still fit above the sub-tab content, or does it need trimming for the narrower space one level deeper?
  • The floating "+" add-holding FAB currently only shows on Stocks/MF — should it also appear on the new top-level Fixed Income/Precious Metals/Retirement/Real Assets tabs (it doesn't today either, so likely no change, just confirming).
