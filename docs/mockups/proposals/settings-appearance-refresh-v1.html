Notes

  • Option 1 keeps the most information density (icon + label per theme, precise size steps via a slider) while looking noticeably cleaner than the fake-mini-screenshot swatches — the slider pattern is instantly recognisable from iOS's own Text Size control, so it costs no learning curve.
  • Option 2 is the lightest-weight visually but the theme dots lose the "see the real palette" quality your current swatches have (`docs/DESIGN_GUIDELINES.md`'s "Live, visual controls" principle) — a plain dark/light circle doesn't show what Dark mode's surfaces actually look like the way a mini rendered card does.
  • Option 3 is the most compact but gives up the swatch preview entirely and reads more like a generic settings row than a considered "Appearance" moment — probably too far in the minimal direction for a control this visual by nature.
Recommendation: Option 1. It solves the actual complaint (the theme swatches look busy/dated) without losing the "live preview" principle for the part that still needs it, and the text-size slider is a well-worn, instantly-familiar pattern rather than something invented for this screen alone.
