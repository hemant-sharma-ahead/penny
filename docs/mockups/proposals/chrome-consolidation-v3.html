Findings, assumptions, and recommendation

What this structurally replaces

Deletes MainTabs.tsx's current HeaderLeft (hamburger + wordmark) / HeaderRight (eye + bell) row and the separately-mounted ContextSwitcher bar, and replaces both with one GlobalTopBar-type component: avatar · middle slot (children-provided greeting or title) · the same PrivacyModeSwitcher + RemindersBell components, plus a new plain Settings icon-button (⋮) that calls the same navigation.navigate('MainTabs', {'{'} screen: 'Home', params: {'{'} screen: 'Settings' {'}'} {'}'}) the hamburger calls today. This is a real simplification, not just a reskin — one row instead of two on every screen except Home (which goes from three rows of chrome to one).

Assumptions made (per your brief) — confirm or correct

  • Avatar tap = today's ContextSwitcher modal, gated the same way. Only opens the Personal/Groups switcher when the sync entitlement is on, same as today's conditional {'{'}hasEntitlement('sync') && <ContextSwitcher />{'}'}. Open question not addressed here: what the avatar does for non-sync-entitled users — nothing (dead tap target), or open Settings/Profile instead? Needs an explicit answer since v2/v3 both assumed sync is on.
  • Bar is structurally identical across Home, Portfolio, Chip, Expenses, Goals — confirmed above for the three requested frames; Expenses/Goals follow the same pattern as Portfolio (their own PageHeader trimmed of its duplicate title, same as Portfolio's).
  • Chip gets the bar too, closing the exact gap v2 flagged (no PageHeader today) — shown above.

One consolidation flagged, not yet decided

Once the bar's middle title says "Portfolio", Portfolio's own PageHeader repeating "Portfolio" as a title directly below it is literal duplicate text — the same "don't repeat what the header already shows" issue as any redundant summary card. The mockup above assumes the fix: trim the title line from Portfolio/Goals/Expenses' PageHeader, keeping only their stat row (total/return%, counts, etc.) and any tabs. This touches PageHeader usage on three screens beyond the chrome component itself, so it's called out explicitly rather than silently bundled in.

Minor information-loss note (not proposing a fix, flagging only)

Today's ContextSwitcher bar shows the active context's name ("Personal" or a group name) glanceable at all times. Once that's folded into an avatar tap, the current context is no longer visible without tapping — a small regression in "where am I" legibility. Not solving this here since it wasn't asked for and risks re-adding the second row this whole change removes; flagging so it's a conscious tradeoff, not an oversight.

Recommendation: left-aligned middle content, plain (non-ringed) avatar. Left-alignment keeps the new bar visually consistent with every existing PageHeader title in the app (all left-aligned today) — centering would be the one inconsistent title treatment in the whole app for no functional gain. Plain avatar avoids double-signalling privacy mode: the eye icon is already the explicit, named control for that; a second passive ring on the avatar reads as decoration once there's a direct control doing the same job, and it was the one thing in v2's Concept C that never had a clear purpose beyond looking distinctive. Also recommend trimming Portfolio/Goals/Expenses' PageHeader title line per the consolidation note above — leaving it in place ships a visible duplicate on day one.
Confirm before implementation:
  • Avatar behavior for non-sync-entitled users (no-op vs. Settings/Profile shortcut).
  • Left-aligned vs. centered middle content (recommendation: left-aligned).
  • Plain vs. mode-ringed avatar (recommendation: plain).
  • Trim Portfolio/Goals/Expenses' PageHeader title line, yes or no (recommendation: yes).
