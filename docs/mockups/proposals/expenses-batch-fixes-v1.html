Plots this year's months against last year's — no natural "prior" for all-time. Omitted.
Recommended approach: omit, don't fake. For every element listed above, don't retrofit a pseudo-comparison (e.g. diffing against "average of all prior years" for a recap badge) just to keep the card present — that produces a number nobody asked for and that doesn't mean what the badge's label implies. All Time should read as a clean, confident set of lifetime totals and breakdowns; comparison-shaped UI stays exclusive to Monthly/Annual, where "previous period" is unambiguous. If a lifetime "trend" view is wanted later, that's a distinct, deliberately-designed feature (e.g. a year-over-year bar chart with no single "previous" to falsely highlight) — not a retrofit of these existing comparison widgets.

Batch summary

  • ① Bulk hashtag — 4th icon (ti-hash, labelled "Hashtag") added to the existing 3-icon bulk-action bar, before Delete. Opens a centered modal reusing ExpenseForm.tsx's Frequent-tag chips + search/create input; explicitly additive (adds to each selected transaction's existing tags, never replaces).
  • ② Already-imported bucket — flat list rows become paired Statement/Recorded-style cards (MatchedBucket.tsx's exact visual language), now also surfacing the matched expense's category and account. "Not a duplicate — import anyway" escape hatch preserved per pair.
  • ③ Analytics All Time — segmented control widened to 3, same visual treatment, no new nav paradigm. Totals/breakdowns carry over unchanged; every period-over-period comparison element (recap delta, anomalies, spend velocity, Biggest Movers, MoM/YoY chart) is omitted rather than faked with a nonsensical "previous period."

All three are mobile-only — apps/web-react is frozen (2026-07-31), so none of these need a web-react mirror; that platform check is resolved by project policy rather than by a live parity comparison.
