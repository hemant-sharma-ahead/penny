What's new here vs v3
  • Tapping "Mark as paid" no longer finalizes immediately — it swaps the button for three equal-weight choices: Log a new expense / Link an existing expense / Skip. None is visually favored — the whole point is it's optional.
  • Log a new expense shows a pre-filled preview (description = policy name + "premium", amount = the exact discount-aware installment amount, category = the real cat-insurance-premium "Insurance Premium" category) before a separate confirm tap — nothing saves silently.
  • Link an existing expense shows 3 plausible recent expenses near this amount/date as tappable rows — a lightweight picker, not a full search screen, per scope.
  • Skip is exactly v3's original behavior — one tap, no ledger interaction, no penalty for choosing it.
  • The Payment history list now tags each row with what happened: + logged as expense / 🔗 linked to … / no tag at all for skipped ones. Try all three from the panel above and watch new tagged rows appear at the top.

Mark as paid — per-installment discount, now with optional expense-linking

The per-installment math from v3 is unchanged: ₹12,000 annual premium, 10% first-year discount, Monthly frequency → ₹900/mo Year 1, ₹1,000/mo Year 2+. New in v4: after the amount is determined, "Mark as paid" no longer silently records a payment-history row — it offers the optional 3-way choice below. Try it live in §②'s interactive form above.

decided (v4) "Mark as paid" → optional expense-linking. Per the user's exact framing — "it should log a real expense or ask the user to link up an existing expense entry, should not be mandatory though" — the three choices (Log new / Link existing / Skip) are given equal visual weight, deliberately: none is styled as the "recommended" path, so nothing nudges toward creating a duplicate ledger entry for someone who already tracks this payment another way (bank import, SMS tracking). The category used for "Log a new expense" is the real default category cat-insurance-premium / "Insurance Premium" (ti-shield, #3b82f6) from packages/core/src/core/db/defaultCategories.ts — not invented. "Link an existing expense" is intentionally a short list of plausible nearby expenses in this mockup, not a full search UI — a real implementation would query recent Expense rows by date-proximity to the due date and amount-proximity to the installment, which is a reasonable v1 heuristic but not designed further here.
micro-interaction The choice panel appears exactly where the "Mark as paid" button was (button hides, panel shows in its place) — never a full-screen modal, per the instruction to keep this lightweight given it's an optional enhancement on an already-quick action. Picking "Log a new expense" or "Link an existing expense" reveals one more short sub-step (a pre-filled preview to confirm, or a 3-row picker) with a "← Back" escape to the 3 original choices; picking "Skip" finalizes immediately, identically to v3. Whichever path is taken, the same confirmation flash + rolling-forward-by-one-interval + payment-history-row behavior from v3 fires at the end — only the row's tag differs.

Design decisions made, and open questions

Decided this round (v4 — final)

  • decidedModal loading % — keep the simple even-division (annual ÷ frequency) math from v3; no new field added. Real insurers' small monthly/quarterly surcharge (confirmed via WebSearch in v3, ~3–5%/yr) stays a documented simplification, not modeled.
  • decidedReminder volume — up to 12 reminder occurrences/year for a monthly-pay Term policy is fine as-is; Snooze/Done (already in RemindersBell.tsx) are considered sufficient, no separate throttling designed.
  • decided"Mark as paid" → optional expense-linking — three equal-weight choices (Log new / Link existing / Skip) appear inline where the button was tapped. Full rationale and the real category source (cat-insurance-premium) in §④.

Decided in earlier rounds (v1–v3, unchanged)

  • Nominee(s) and "Premium payment term" are Term/Life-only, hidden for Single premium. First-year discount is a one-time year-1 modifier. Duration presets and insurer lists are type-scoped. Vehicle insurance fields stay unlinked from Real Assets' own Vehicle-holding fields. Switching type silently resets the insurer. Age-based duration chips read the saved profile DOB locally. A custom "Other" insurer is remembered as a local suggestion. Life's ULIP toggle picks the correct 3-yr/5-yr revival window. Reminders integration reuses RemindersBell.tsx exactly, with a new "Mark as paid" action.

Open questions

  • confirmShould "Link an existing expense" restrict its candidate list to expenses tagged with the Insurance Premium category, or show any recent expense near the amount/date regardless of category (a payment made before this feature existed likely wasn't categorized as Insurance Premium at all)? Not designed further — the mockup's 3-row example is illustrative only, per scope.
  • confirmIf a payment is later un-marked or corrected, should a linked/logged expense be automatically unlinked/deleted, or does that require its own explicit undo flow? Out of scope for this mockup, flagging as the natural next question once "Mark as paid" ships.
