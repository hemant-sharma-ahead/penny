Accounts list — round 3: real brand fallbacks + a redesigned action affordance

Direct response to feedback on round 2 (account-list-redesign-v2.html). Four things changed here: (1) BankLogo.tsx now has a 4th real logo (HSBC) and 3 verified official brand colors for presets that still have no licensed mark (SBI, Kotak, IndusInd) — used to tint the generic fallback icon, never to fabricate a logo. (2) The bolted-on 4-icon action row that made every option look worse is rebuilt — Options 2, 3 and 4 (the three you called out, plus Option 1 as a bonus) now each offer three genuinely different interaction models for surfacing the same 3 real actions, toggle-able live below, not just a re-skin of the same always-visible row. (3) Your own idea — making "view transactions" an explicit icon instead of an invisible whole-card tap — is built out fully in two of those three models. (4) The real action logic is unchanged and re-verified against AccountList.tsx: RECONCILABLE = ['cash', 'wallet'], STATEMENT_IMPORTABLE = ['bank','credit_card'], both partition every AccountType with no overlap, so every account still gets exactly 3 real actions ((Import or Reconcile) + Edit + Delete) — the "view transactions" affordance in the new models is a 4th, purely discoverability-driven addition, layered on top, never a replacement for the whole-row tap which still does exactly what it does today.

Recommendation
Lead with Model 2 (view icon + kebab) as the interaction model, applied to Option 4 first, Option 2 second.
  1. Option 4 (soft-tinted flat card) + Model 2 — the strongest combination on the table: keeps the per-account brand identity that made this option distinctive, while cutting the always-visible action count from the "wrecked the card" 3–4 down to 2. This is the one I'd actually ship first.
  2. Option 2 (dense list) + Model 2 — for the density-first crowd; the two-line-per-row problem round 2 introduced disappears once actions default to collapsed, restoring the original single-line compactness while still surfacing every real action.
  3. Option 3 (grouped) + Model 2 — worth keeping in reserve rather than shipping alongside Option 2: it's the same row treatment, just reorganized by type, and only earns its extra section-header overhead once an account count grows enough that "how much do I have in the bank vs. what do I owe" becomes a real scanning problem. Ship Option 2 first; revisit Option 3 if/when that threshold is hit.
Why not Model 1 or 3 as the lead: Model 1 answers your literal ask most directly, but the comparison table's own numbers say it plainly — it's still the busiest of the three at rest, and Option 1's grid tiles prove it's the one that runs out of room first. Model 3 is the most interesting idea for a future "trust the user to explore" pass, but shipping it without a companion onboarding nudge risks recreating the exact complaint that started this whole thread (an action with no visible affordance) — one dot is better than an invisible whole-card tap, but only slightly.
Both of the interaction models built out here that literally add a "view transactions" icon (2 and 3) still leave the current whole-row/card tap working exactly as it does today — nothing about the real onPress={() => setViewingAccount(acc)} behavior in AccountList.tsx is removed or changed by this proposal; the icon is purely an added affordance for discoverability, per your framing of the idea.
Cross-platform status

apps/web-react's AccountList.tsx is frozen (2026-07-31) and unchanged since round 2's finding: plain IconBadge (generic icon + the account's own color field, never a real logo or a brand-color tint) + name + type label + balance, inside a ListContainer. Re-read this round to confirm nothing drifted: web has no Import-statement action at all — its action row is only Reconcile (cash/wallet) + Edit + Delete, and there's no tap-to-view-transactions drill-down/modal either (no onClick on the row, no equivalent of mobile's AccountDetailModal). That's a real, standing disagreement between the two platforms on top of the logo/tint gap already flagged in round 2 — expected and accepted, since web is a historical reference only and this redesign (including the new "view transactions" icon) is mobile-only; no web-react mirroring is proposed.
