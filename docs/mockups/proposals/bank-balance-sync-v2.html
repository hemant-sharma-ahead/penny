Bank Balance Sync — Implementation-Ready Spec v2

Refinement round on docs/mockups/proposals/bank-balance-sync-v1.html (kept intact, not edited). v1 was a decision gallery; this is the single finished spec — every real state, exact copy, and the full Direction C interaction chain as connected frames. Same HDFC savings ledger and real numbers as the simulation throughout (§7b/7c/7d, §11a/§11b, §13, §14/§14b) — nothing invented except decorative balances on accounts the simulation never covers (ICICI Savings, Cash Wallet, HDFC Credit Card — clearly labelled as such).

What changed since v1, and why — read this before the frames below:
  • Direction C is the only direction shown now — approved 2026-08-08, no alternates re-presented. Every state that direction needs (loading / empty-verified / never-imported / collapsed-mismatch / expanded-mismatch / dismissed) is spec'd for the first time here; v1 only ever showed the "expanded mismatch" happy path.
  • Two diagnostic signatures need two different "Investigate" destinations — a gap v1's §5 left unwired. "Steps in partway" (§7b/7c) has a real two-row window to point at, so "Investigate" drills into the transaction list (Frames 3→4 below). "Flat from day one" (§7d) has no such window — every checkpoint disagrees, including the first, so there's nothing to scroll to. Its "Investigate" instead opens a dedicated opening-balance check (Frame 2b) — reusing the same anchor-strip visual language already built for Surface 6, not a new pattern. Flagged as a v1 gap, fixed here, not a new open question.
  • The account-list badge only ever means one thing: "needs a look." Absence of the badge is ambiguous by itself (verified vs. never-imported look identical at list level, on purpose — neither needs action, so neither earns list-level clutter per "uncluttered first"). The account detail view is where that ambiguity gets resolved, with three distinct calm states (Frame 2a/2b/2c below) — this two-tier resolution is a deliberate v2 decision, not an oversight.
  • Dismissing is per checkpoint-pair, never global, and never makes the mismatch vanish without a trace — a dismissed variance shows a quiet, muted acknowledgement line in the account detail (Frame 2f) rather than reverting to silence, so it stays legible/honest (§1 of the guidelines: "if something is masked... make it legible why and how") without nagging.
  • One control, reused everywhere it applies — the "I've reviewed this, dismiss" action is the same control in the compact snapshot (Frame 2) and the full timeline escape hatch (Frame 4), not two separate dismiss mechanisms to keep in sync.
