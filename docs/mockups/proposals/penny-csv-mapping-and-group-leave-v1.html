Confirmed — final direction: sectioned + collapsible. The flat single-list alternative (the previous "Option 1" — all 11 rows in one continuous list) was considered and rejected: it pushed Back/Continue well off the fold on a screen most users only ever touch once per custom source, where "uncluttered first" and "progressive disclosure" (§1) both point at grouping instead. The three-tier split (Required / Common / More fields) mirrors a real usage split — Category/Account/Payment mode/Notes show up in most Indian bank exports, while Tags/Type/Bank name/Account type are genuinely rarer — and "More fields" auto-expands with a "N auto-matched" badge whenever it holds a value the matcher already found, so collapsing is only ever a size reduction, never a way to accidentally miss something real. Reuses the exact chevron-header disclosure pattern already shipped for DuplicatesBucket.tsx's grouped tiles, and models "Transaction type" as its own segmented text-column-vs-income-flag choice mirroring the existing Amount split control — no new interaction invented anywhere on this screen.

Parity confirmed separately: a fully-populated Custom mapping now behaves identically to picking the Cashew/MoneyView preset directly — nothing downstream of the ColumnMapping object branches on which format produced it, and parseFlexibleDate's date hint already resolves identically ('auto') for custom/cashew/moneyview. The only reason full parity wasn't reachable through the actual UI before this item was that MapColumnsStep.tsx had no manual picker at all for Tags/PaymentMode/BankName/AccountType/Type — this design closes exactly that gap, not just adding visibility for its own sake.

80Groups: leaving a group should keep local history visible, read-only
leaveGroup() (groupsService.ts) deletes the local groups record and the user's own membership row immediately — group_events rows are left behind but orphaned (nothing can query them once the owning groups record is gone), so the group and its whole history vanish from the device the moment you leave.
Plan: keep the local groups record and its group_events intact on leave, marking the group with a new status alongside the existing closeGroup/reopenGroup mechanism, so GroupDashboard.tsx renders it read-only — history visible, new activity/admin actions disabled, banner explaining the user left.
Existing "read-only past state" pattern found and reused: a closed group (settled & closed) already hides Add expense/Settle up, disables per-row edit/delete/flag (canAct = group.status === 'active'), and disables member-row settle actions. The design below extends that exact mechanism with a new status (e.g. 'left') rather than inventing a second read-only visual language — the per-row action gating already keys off status === 'active', so it needs zero new code once left is a distinct status value, not 'active'. Confirmed, final scope: the two states are now fully unified — closed's plain-text explanatory line is upgraded to the same real Banner component left uses (own copy per state), shown in the updated "closed" frame below.
