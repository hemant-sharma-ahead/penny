Insurance Add/Edit form — 5 layout/structure options (v1)

Grounded in the real shipped code, read fresh: apps/mobile/src/features/insurance/PolicyForm.tsx + its fields/{'{'}TermLifeFields,HealthFields,VehicleInsuranceFields,HomeFields,TravelFields{'}'}.tsx siblings, Chip.tsx, InsurerField.tsx. The shipped form (built from insurance-redesign-v4.html) has 14+ controls stacked in one scroll for Term: type tiles → plan name → insurer → policy number → start date → duration chips → end date → premium+frequency → discount → installment preview → payment schedule (due date, mark-as-paid, history) → Sum assured + premium-payment-term + nominee → notes. Two confirmed problems drive every option below: (1) Sum Assured sits after all the payment mechanics, reading as buried; (2) "Till 60/65" duration chips silently did nothing with no saved DOB (now toast-fixed in code, but a toast-after-the-fact isn't a real design — the missing prerequisite should be visible in the form itself). Mockup only — no app code touched.

trade-off Great for a first-time "buy this policy" flow (which is what Acko/PolicyBazaar's research is actually optimizing — new-customer underwriting funnels, not a personal record-keeper). ③ Option 2

Single scroll, reordered by importance

Same one-page shape as today — smallest structural change of the 5 — but Sum Assured + Premium move to right after Type/Insurer/Name, and everything payment-mechanical (frequency, discount, due date, mark-as-paid, history) demotes into one clearly-labeled, collapsed-by-default "Payment schedule" sub-section with a one-line summary — reusing Penny's own existing "Collapsible More fields disclosure" pattern rather than inventing a new one.

④ Option 3

Card / accordion sections — named, scannable, one open at a time

"Coverage & Premium" auto-expands by default (it's the primary content, same auto-expand-if-important precedent as Penny's existing "More fields" disclosure) — the other three start collapsed. Tap any header to expand/collapse.

⑤ Option 4

"Key facts" dashboard-style entry

Inspired by how Jupiter/Groww-style fintech apps foreground one dominant number before secondary detail, and Penny's own "Big Number Hero" pattern already used elsewhere (Real Assets card mockups). The 2-3 biggest numbers become large tappable tiles filled first; identity is a compact strip; everything else sits in a visually quieter scroll below. This is also where the DOB dependency gets its most prominent treatment of all 5 options — a first-class dashboard tile of its own, not a caption.

⑥ Option 5

Guided, one question at a time — a genuinely different paradigm

Distinct from the wizard (which groups several fields per step): here exactly one field fills the whole screen at a time, Typeform/Turtlemint-style guided-capture — with a running summary strip pinned at the top that fills in as you answer, so context is never fully hidden the way a strict one-question flow normally loses it. Single-choice questions (type, frequency) auto-advance on tap; numeric/text ones need an explicit Next. Tap through it.

⑦ Required fix, across all 5

The code fix (a toast on tap) is already shipped this session — but a toast that appears only after the user has already tapped a seemingly-normal chip is a symptom fix, not a design. recommendation Lead with Option ③ (Accordion sections). It fixes both confirmed complaints as directly as any option (Sum Assured auto-visible, DOB gap surfaced inline), reuses a pattern this codebase already has (no new interaction paradigm to design, build, and test), and — unlike the wizard or guided flow — stays just as good for editing an existing policy as for adding a new one, which matters here because PolicyForm.tsx is genuinely both. It also visibly generalizes to every insurance type without change (shown for Vehicle above), where the wizard's 4 steps and the guided flow's 8 questions would need type-specific step/question counts to avoid feeling padded for a 3-field type like Home.

Option ② (reordered scroll) is the pragmatic fallback if even the accordion's tap-to-expand interaction feels like too much change for how small this problem actually is — it fixes both complaints with the least implementation risk, at the cost of not really shortening the form.

Option ④ (dashboard tiles) is worth a second look specifically if the real goal is closer to "make this feel like a premium fintech product" rather than "fix two bugs" — its DOB treatment is genuinely the best of the 5 and its hero-number treatment the most visually confident — but it's the option most likely to need a second design pass to get the "muted details" section feeling truly de-emphasized rather than just visually inconsistent with the tiles above it.

Options ① (wizard) and ⑤ (guided one-question) I'd deprioritize for this specific form, not because they're bad patterns generally (they're real, validated patterns — Acko and PolicyBazaar's own data backs the wizard) but because both are optimized for a job this form doesn't have: acquiring a new customer through a sales funnel. Penny's Insurance form is a personal record-keeper used for both adding and, likely more often over time, editing — and both patterns make editing measurably worse to make first-entry marginally better.
