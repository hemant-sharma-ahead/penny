5 — Monthly Cash Flow card (Analytics)
Not a new "Cash Forward" transaction type — a computed summary card for the selected month, using your existing cash-account balance + transactions. If you reconciled that account this month, it also shows the gap between what your logged transactions say and what you actually counted — the one genuinely useful part of the Money Manager idea, done as an insight instead of a monthly ritual.

How the Cash Flow card computes (all from existing data, no schema change)

  • Initial cash — the account's balance as of the 1st of the selected month, reusing computeBalance() (`core/accounts/balanceCalculator.ts`) bounded to transactions before that date. Already a pure function, no new logic needed for this part.
  • Cash income / Cash expenses — sum of income/expense-type transactions on that account within the month, excluding any "Balance reconciliation" entries (a fixed, already-unique description `useAccounts.ts`'s `reconcileAccount()` posts) — kept separate so "computed" reflects only what you actually logged, not a correction.
  • Computed left = Initial + Income − Expenses. This is the arithmetic you described.
  • Variance note — only rendered if a reconciliation happened during the month: compares Computed Left against the reconciled actual balance at that point, surfacing the gap as a number, not silently absorbing it into "Cash expenses."
  • Scope: shown per cash-type account (not bank/card, which already have a clear paper trail). If more than one cash/wallet account exists, one card per account, same as today's per-account balance list.
