Global chrome consolidation v4 — no bar, just the top of the page

Same agreed structure as v3 — avatar (left) · greeting/title (middle) · eye + bell + ⋮ (right), one row, identical everywhere — but re-executed so it stops reading as "a header": no white strip, no border, no boxed icon buttons. It's the same background as the page underneath it, so it feels like the top of the content, not chrome sitting on top of it. Skipping the "today" comparison and style-variant gallery this round — direction is decided, this is the one confident cut.

What changed from v3, concretely: the row's background is --bg (identical to the body), not white — no seam between "chrome" and "content." No bottom border/mode-accent line. Icons lost their circular button backgrounds — they're just glyphs now, coloured (privacy = amber) instead of boxed, with generous tap spacing instead of a tight toolbar-height row. The avatar is a touch bigger (38px) with a soft shadow instead of a flat fill, so it reads as a personal identity mark, not a nav-bar leading icon. Greeting/ title text is bigger and bolder (18px/800) — closer to how GlanceHeader's own numbers already lead with a big, confident figure, so the top of the screen feels continuous with the content below it rather than a distinct rail above it.

Why this reads differently, and what's still open

Removing the white background + border was the single biggest lever — that hard edge is what made v3 read as "a header component" no matter how its contents were arranged. Once the top row shares the page's own background and the icons stop being boxed buttons, the same information (avatar, greeting/title, three controls) reads as the top of the page rather than a fixed rail bolted onto it — closer to how a lot of modern, well-regarded apps treat their "top," as an extension of the content rather than a distinct system layer.

Everything functional from before still holds: avatar opens the same context-switch modal, eye/bell are the same real components, ⋮ is a plain direct Settings tap — nothing about behavior changed, only the visual weight of the container.

Recommendation: go with this. It keeps the exact structural agreement from last round while actually answering "make it feel less like a header" instead of re-decorating the same box.
Still open from last round, unresolved by this pass:
  • Avatar behaviour for users without the sync entitlement (no context-switcher exists for them today).
  • Trimming Portfolio/Goals/Expenses' own PageHeader title line (shown already trimmed above).
