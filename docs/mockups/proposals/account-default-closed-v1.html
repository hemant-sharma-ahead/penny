Recommendation: ship as designed here. §2's same-account exclusivity intentionally skips the confirm popup — auto-clearing your own other flag on the same account you're already editing isn't a surprise the way silently changing a DIFFERENT, off-screen account's flag would be (§3, which does get one). Everything reuses shipped visual patterns (Toggle rows, `ConfirmDialog`-style popup, the IOU Archived-section chevron) — nothing here is a new component.

Judgment calls & open questions for review

  1. §1 Closed-while-Default-on — modeled as the Closed toggle rendering fully dimmed/disabled rather than tappable-then-auto-clearing-Default. Either reads fine; picked "disabled" so the two rows never visually flicker against each other on a single tap. Flag if you'd rather it be tappable with an auto-clear like the reverse direction (§2) is.
  2. §3 popup copy — names the specific account losing default ("HDFC Salary") rather than a generic "another account" — more concrete, costs nothing since the form already knows which account currently holds it.
  3. §4 Closed section scope — one shared "Closed (n)" section spanning all account types (mirrors IOU's single Archived section for all persons), not a separate closed sub-list per type group. Simpler, and closed accounts are expected to be rare enough this shouldn't get long.
  4. §4 Closed row actions — kept Edit (the only way back to un-close) and Delete; dropped Import/Reconcile from the revealed row for a closed account, since neither makes sense for something no longer operational.
  5. Scope note, not shown here — Account.isArchived is a separate, distinct, already-existing-but-unused field (per your own Closed-vs-Archived distinction) — this mockup doesn't touch it or build an Archive feature; that stays a future, separate piece of work.
