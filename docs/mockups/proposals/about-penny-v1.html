Design notes

  • Header hero. Real app icon (apps/mobile/assets/icon.png, referenced directly in this mockup) at 68px, rounded 18px to match the OS-rendered icon shape, "Penny" name below, then a small pill showing the live version string. No build-number field — none exists in app.json, so none is shown. Version reads Constants.expoConfig?.version, the exact pattern FeedbackPage.tsx already uses (APP_VERSION) — not a new sourcing mechanism.
  • Mission statement. Verbatim, centered, de-emphasized (italic, secondary text colour) under the hero — a single line, not a card, so it doesn't compete with the two real controls below it.
  • Our Privacy Promise row. Deliberately styled with more visual weight than a plain settings row — a filled primary icon badge (ti-shield-check), matching the tone of the destination screen it opens (PrivacyPromiseScreen.tsx's own primary-filled shield icon + "Our privacy promise" heading). The sub-copy ("0 bytes readable by us, 0 trackers, AES-256...") previews real pillars from that screen (not invented) so the row reads as a doorway to something substantial, not a generic settings link. Navigates to the existing PrivacyPromise route — no new screen needed for this piece.
  • What's new. Plain SectionLabel + grouped card, exactly like every other Settings section — the 4 bullets are static text (no chevrons, nothing tappable), each with a small ti-sparkles marker instead of a bare dot, reusing the "grouped cards" pattern rather than inventing a changelog-specific component for 4 lines of text.
  • Settings entry point. Appended as the last row in the existing "Data & activity" card, after Discover Penny — same Row shape and section accent colour (theme.neutral) as its four siblings, sub-copy in the same descriptive style as SMS Tracking/Discover Penny's rows. Placed last because it's the lowest-frequency, purely-reference item in that card — every other row in "Data & activity" is something you'd actually go tap to do something (back up, message support, review an SMS parse); About Penny is look-then-leave.
Cross-platform check (per ui-design-check): apps/web-react has no equivalent About/version screen today, and — since web-react is frozen (no further changes) — this stays mobile-only by design, the same documented exception already made for PennyLoader and the "Did You Know" tips components. No parity gap to flag: there's nothing on web to disagree with, and nothing to mirror there.
