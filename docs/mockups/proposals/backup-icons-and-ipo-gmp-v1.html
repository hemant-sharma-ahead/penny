Backup icons & IPO GMP — polish proposals (v1)

Two small, unrelated apps/mobile polish requests, bundled into one file per this project's "one HTML file per discussion" convention (they were raised together, but are separate discussions — see the two clearly separated sections below, each with its own anchor nav and recommendation). Nothing here is final and no app code has been touched — both sections are grounded in the real current source (AutoBackupCard.tsx / BackupPage.tsx / IpoTab.tsx, read in full first) and in real, verified Simple Icons brand data (see the finding below) rather than an invented palette.

cross-platform check — backup icons apps/web-react/src/features/backup/AutoBackupCard.tsx read for comparison. Web still uses the old 3-way SegmentedControl (This device / Drive / iCloud tabs) — it was never migrated to the tap-to-reveal accordion (mobile's "Option B", shipped this session, docs/mockups/proposals/backup-restore-redesign-v1.html). This is an expected, already-flagged divergence: apps/web-react is frozen (CLAUDE.md), so this icon/button proposal is mobile-only and needs no mirroring. Flagging per the ui-design-check methodology rather than leaving it implicit.
cross-platform check — IPO GMP apps/web-react/src/features/portfolio/ipo/IpoTab.tsx read for comparison. Web has the identical inline two-way GMP treatment in the left column, down to the same logic (gmpValue > 0 ? green : gmpValue < 0 ? red : tertiary) — except web still hardcodes raw hex (#10b981/#ef4444) where mobile already uses theme.success/ theme.danger tokens, a small pre-existing drift not introduced by this task. Both platforms currently agree on this screen. Since web is frozen, this GMP redesign is mobile-only; after implementing, the two platforms will intentionally diverge until any future react-native-web unification — documented here as expected, not a leftover bug.
real constraint — verified against Simple Icons' own data Fetched the actual simple-icons package metadata (icons.json, the same source BankLogo.tsx's doc comment describes checking) rather than assuming: Google Drive = #4285F4 (flat Google-blue glyph — Simple Icons does not ship a literal multi-color green/yellow/blue triangle mark; that particular rendering doesn't exist as a redistributable flat SVG path anywhere reputable, so "real Drive triangle in its 3 colors" as literally described in the ask isn't available — the single-color blue mark below is the real, verified substitute). Apple = #000000 (pure black, monochrome by Apple's own brand guidelines — Apple never publishes a colored mark). iCloud has its own slug in Simple Icons, but its glyph is a plain cloud outline at an arbitrary #999999 gray with no real distinctive brand identity (Apple doesn't define an official "iCloud color") — not more recognizable than today's neutral icon, so this proposal keeps the existing ti-brand-apple choice for the iCloud row (the real Apple mark) rather than swapping to Simple Icons' generic gray cloud shape.
theme-contrast risk Apple's real hex is pure black — invisible on a dark-theme card background if used as a fixed literal. Recommend a theme-keyed swap (black in Light, white in Dark) for the Apple mark specifically — this mirrors Apple's own guidelines (they ship the mark in both black and white for exactly this reason), so it's not "overriding a real brand color" the way BankLogo.tsx's doc comment forbids, it's picking the correct one of Apple's two officially sanctioned variants per background. Implementation should key this off the theme mode explicitly (theme.mode === 'dark' ? '#fff' : '#000'), not off theme.textPrimary, so it can't silently drift if that token's exact shade ever changes for unrelated reasons. Drive's blue (#4285F4) needs no such override — it passes contrast in both themes as one fixed color, same as BankLogo.tsx's bank marks. Toggle Light/Dark below to check this yourself.

Section 2

IPO tab — GMP redesign with RAG coloring

Scope: apps/mobile/src/features/portfolio/ipo/IpoTab.tsx's renderIpoCard. Today GMP renders as plain inline text buried in the left column, colored only two ways (green if gmpValue > 0, red if < 0, tertiary/dash otherwise). This moves GMP to a distinct right-side element and applies real three-tier RAG coloring, shown across all 4 real card states (upcoming / open / closed / listed) so no state is silently dropped.

revision, 2nd pass — added after real feedback on Options 1 & 2 You liked the corner-badge direction in principle, but flagged two real problems: the cards got taller (Option 1's badge stacks label/value/% across up to 3 lines inside a brand-new header slot, on top of a body that was otherwise unchanged) and information got lost — comparing against the real code while building the "Current (today)" frame below caught that both Options 1 and 2's listed example had actually dropped listingGain ("Listed +X%"), the real headline stat for a listed IPO today, showing only the muted historical "GMP was" figure instead. Fixed in place above — both options now show both figures, matching the real card, and are kept for comparison per your instruction. §2b below adds 6 new options built around one constraint taken directly from this feedback: none of them add a new line/row for a status that already has somewhere for GMP to live — each merges into or reuses an existing line instead, which as a side effect makes several of them shorter than today's real card, not just no taller.
threshold is a proposal, not a fact — needs your sign-off There's no existing amber/neutral threshold anywhere in the codebase to inherit, so this is a genuinely new call: Red = gmpValue < 0 (trading below issue price — expect a listing loss). Amber = 0% ≤ gmpPercent < 8% (a modest/uncertain premium — grey-market quotes swing several % day to day on low liquidity, so anything under ~8% isn't reliably distinguishable from noise). Green = gmpPercent ≥ 8% (a premium large enough to read as a real bullish signal, not noise). Unknown (gmpValue === null) stays a plain neutral dash, outside the RAG system entirely — same as today. 8% is a starting proposal, not a researched cutoff — happy to move it if you have a different number in mind.

Review checklist (per .claude/skills/ui-design-check/SKILL.md)
  • Tokens: every non-brand color above maps to an existing semantic token (theme.success/danger/warning/textTertiary/primary). Only the two documented brand exceptions (Drive blue, Apple black/white) are new fixed hex values — same class of exception BankLogo.tsx and the design guidelines' §5 "domain/brand accent" carve-out already allow.
  • Modals: n/a — neither change touches a modal.
  • Back button: unaffected — both screens keep the existing global header back-chevron.
  • Z-index: n/a — no new overlay/modal layer introduced.
  • Privacy-mode reactivity: n/a — none of these new colors are backgrounds/accents that should tint with Safe/Open mode (backgrounds are theme-reactive only per the 2026-07-31 decision); brand marks and RAG status colors are identity/status colors, not mode-reactive chrome.
  • Consistency with itself: the Drive/Apple marks would be the same DriveLogo/AppleLogo component used at both call sites (row icon + Restore button), so there's exactly one place to update if a mark ever changes — no duplicate copies to drift.
  • Duplicated capability: neither change adds a second control for something that already exists elsewhere — this is a pure visual/weight change on controls that are already the sole owner of their capability (Backup screen was already consolidated 2026-07-27; the IPO card's GMP display has only ever lived in one place).
