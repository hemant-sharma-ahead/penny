SMS Parser Verifier — unified workspace

Direct response to real usage feedback: the 3-mode split (Known templates / Test your own / Add a parser) was three disjoint destinations for what is actually one continuous job — browse what's configured, test real messages against it, fix what's missing, right where you found the gap. This redesign merges all three into one bank-centric workspace, makes both templates AND sender patterns editable (not just append-only), adds a full-bundle export, upgrades the results table to show highlighting + match trace without clicking, decouples sender-recognition testing from regex testing, and adds a grounded regex-writing helper.

Every point you raised, and what changes
1. "Why 3 different tabs?" → Gone. One sidebar list (banks + a pinned "Bulk test" entry), one workspace per selection. Editing/adding a template is now just part of browsing a bank, not a separate destination.

2. "Add a template to an existing bank doesn't let us define the sender" → Sender ID patterns are now editable for every bank, official or not — official patterns stay visible and locked (a real bank's actual shortcodes shouldn't be silently deletable), but you can add as many of your own patterns as you find (a bank issuing SMS from a new shortcode is a real, common thing).

3. "Can't change known templates" → Every template card now has Edit. Editing an official template creates a session-local override (badge flips official → modified, with a "revert" action) — never mutates the real shipped data, same safe drafting model as adding a new one.

4. "No way to download everything into a worker-compatible format" → A global "Export all patterns" action, reachable from the sidebar, dumps the CURRENT effective bundle (official + every override + every draft, across every bank) as JSON. Confirmed identical shape to workers/api-proxy's real /sms-patterns response — this isn't a guess, verified against that route's actual handler.

5. "The table could show highlighting and the match trace inline" → Done — the Message column renders live color-coded highlighting directly (not gray plain text), and a compact trace-strip (● ● ○ per template, colored by outcome) sits right next to it. Expanding a row is now for the deep dive (field chips, "add pre-filled"), not a requirement just to see what happened.

6. "We should be able to test any sender/message, which is never implied" → Made explicit two ways: the paste box's own placeholder/hint says so directly, AND a new Auto-detect / Force-this-bank toggle lets you test a message's BODY against one specific bank's templates regardless of whether the sender you typed would normally match it — isolating "is my regex right" from "is the sender recognized" as two separate, individually-testable questions.

7. "Give the most-used regex to help write new ones" → A helper panel next to every regex field: common capture-group idioms extracted from the real, already-shipped smsPatterns.ts (not invented), one click to insert at the cursor, plus a general regex-syntax cheat sheet for anyone who isn't fluent in regex at all.

Build this as one redesign, not incremental patches. The 7 points aren't 7 separate small fixes — they're one root cause (three artificially separate destinations for what's really one job) plus its direct consequences (can't edit in place, can't test freely, no way out to a real deployable artifact, too much hidden behind clicks). Fixing them piecemeal on top of the existing 3-mode shell would just be more patches on a structure that needs to change. This is worth doing as a real rebuild of entry.ts's mode/render architecture, not another round of edits to renderAddMain().

Summary of what changes

  • Architecture: mode: 'known' | 'test' | 'add' and the 3-way sidebar mode-switch are removed entirely. Sidebar selection becomes: the pinned "Bulk test" entry, or a bank (existing or newly created) — one workspace renderer per selection, not three.
  • Sender patterns become editable for every bank — official patterns render locked/ non-removable; user-added ones are a new draft concept (customSenderPatterns: string[] per bank, merged into effectiveBundle() alongside existing template drafts).
  • Official templates become editable — a new "override" draft kind (replaces template N of bank X's effective definition for the session) alongside the existing "new template" draft kind; both merge through the same effectiveBundle(), both export identically.
  • Regex ↔ message side by side (new): the regex source's own named-group spans (found by a small bracket-matching parser over the pattern string, not a runtime match) get wrapped in the same colored <mark> elements as the message's capture offsets — both driven by one shared markRanges(text, ranges) primitive, with highlightedText() becoming a thin wrapper over it for the message case. While editing, the regex side re-renders live from the textarea's current value on every keystroke, paired with the template's own bundled sample re-tested against it in real time.
  • Bank-scoped tester lives on every bank's page — Auto-detect (real sender-matching) vs Force-this-bank (skips the sender gate, tests body only) as an explicit toggle, both built on the same traceSms(), just with the sender-gate step conditionally skipped in Force mode.
  • Results table upgrade (applies to both the bank-scoped tester and the Bulk-test page): Message column always renders through highlightedText() (never plain gray text), plus a new compact trace-strip column — reuses the existing per-attempt trace data, purely a rendering addition.
  • Regex helper panel: a static, curated set of capture-group snippets (grounded by grepping the real smsPatterns.ts, not invented) with click-to-insert-at-cursor, plus a second tab for the general regex-syntax reference — available next to every pattern textarea in the tool.
  • Global export: one action serializing effectiveBundle() to JSON — copy or download — confirmed (not assumed) to match workers/api-proxy's real /sms-patterns response shape exactly.
  • Global import (new): the mirror of export — paste or upload a same-shaped JSON, merged into drafts/overrides, never overwriting the bundled official fallback. A bank/template present in both the import and your current session surfaces a conflict badge to resolve by hand, rather than silently picking a side.
  • Kept from the current tool, unchanged in spirit: "Upload a .txt file" for bulk pasting a whole exported message history (now available on both the bank-scoped tester and the Bulk-test page), and both "Copy (redacted)"/"Copy (unredacted)" results actions — redacted stays the easy-to-reach default, unredacted is always one deliberate extra click.
  • Fuzzy "did you mean" sender suggestion (new): a cheap string-similarity check against every bank's existing sender patterns, surfaced only inside an unrecognized-sender row's expanded detail (never cluttering the collapsed table) — turns a dead-end "Unrecognized" result into a one-click "add this as a sender pattern for <bank>" fix when the match is a near-miss.
  • Overlap/duplicate sender-pattern warning (new): before a new sender pattern is added (custom, on an existing bank, or as part of a whole new bank), it's checked against every OTHER bank's existing patterns — a soft warning, not a hard block, since some real-world overlap (a shared aggregator shortcode) is legitimate; the point is making an accidental one visible before it silently shadows another bank's messages.
