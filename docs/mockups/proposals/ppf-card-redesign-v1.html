PPF card redesign — UI proposal (v1) docs/DESIGN_GUIDELINES.md · grounded in the real current PPF card (RetirementCard.tsx's PPF branch, lines ~446–627), ppfCalculations.ts / ppfInterestOnDemand.ts / ppfReviewFlags.ts, and EPF's own already-shipped density patterns (epf-passbook-import-v4.html §0.2)

The PPF card grew four bolted-on additions this session (Import pill, per-FY missing-interest banners, a "N need review" count badge, per-row warning icons) without a step-back pass. This proposal keeps every one of those capabilities but restructures where and how they show up, so the card stays legible whether it has zero issues or several stacked at once. 1What's actually wrong

Diagnosis

  1. The two progress bars are visually confusable. "N yrs to maturity" and "This FY" sit back-to-back, both thin purple/purple-tinted bars at the same width, same track color, same font sizes for their labels. They measure completely different things on completely different timescales (a 15-year lock-in vs a ₹1.5L annual ceiling) but read as one continuous ribbon of "progress," especially once the FY bar turns purple at its own ≥75% threshold — at that point there are literally two purple bars in a row with no visual seam between them.
  2. Every new addition reached for the same amber warning color, regardless of severity. The April tip (a friendly, non-urgent reminder), the missing-interest nudge (an actual data gap), and the review badge (a real calculation mismatch) are three different severities of "you might want to look at this" — but they're indistinguishable at a glance because they're all amber banners/badges of similar size. Nothing tells the eye which one to act on first.
  3. N missing years means N nearly-identical stacked banners. findMissingPpfInterestFys returns every gap, and the card renders one full bordered banner block per entry, each repeating almost the same sentence ("FY X interest not recorded yet — add it, or import your statement") with its own icon and its own "+ Add" pill. Two gap years already pushes the card height up ~40%; three or four (a dormant account re-opened after years away) would make the card mostly banners.
  4. The "N need review" badge is squeezed into the least visible spot on the card. It's a 9px pill wedged next to a 10px uppercase section label — both already small — competing for the same thin strip of horizontal space as the label itself. It represents the same underlying "something needs your attention" concept as the banners above it, just rendered as a totally different UI mechanism (inline pill vs full banner) in a totally different spot.
  5. The Import and Add pills are both filled purple, and there can be up to four purple/amber pills on screen at once (2 banner "+Add" pills, the header "Import" pill, the header "Add" pill) — all roughly the same shape and weight, with no hierarchy signalling that Import and Add are two distinct capabilities, or that the banner Add pills are a shortcut into the same sheet the header Add pill also opens.

Recommendation

Consolidate, don't remove. Every capability above stays reachable — this is a hierarchy and severity-of-color fix, not a scope cut. Concretely:

  • Two-up stat tiles for maturity + This-FY, each in its own bordered box with a coloured top edge — spatially and stylistically distinct, not two bars in a row. This-FY's bar switches to a neutral blue while in progress and green only on completion; it never turns purple, so it can never be mistaken for the maturity bar.
  • One severity tier for "needs a decision," a different tier for "FYI." The April tip becomes a quiet caption line inside the This-FY tile itself (no border, no icon-in-a-box) — it's a timing reminder, not a problem. Missing-interest years and review flags — both genuine data gaps — merge into a single amber "Needs attention" banner.
  • N missing years become chips inside one banner, not N banners. Each chip keeps its own tap target (still opens the transaction sheet pre-filled to that FY's 31 March, exactly as today) — the capability is relocated into a compact chip row, not lost.
  • The review count moves into that same banner as a second line, instead of a squeezed pill next to the section label — same information, a legible spot with room to breathe, and it's back in the same place as the other "needs attention" content instead of a third separate mechanism.
  • Import goes neutral/ghost (matching EPF's own slate treatment of its Import/Export pair), leaving purple exclusively for "Add," the one truly primary action on this section.

Two deliberate divergences from EPF's exact shape

  1. No "N need review" pill repeated in this popup's header. EPF's own list header carries that count again next to its "See all transactions" trigger. Here, the review flag already has one legible home — the "Needs attention" banner on the card (§2) — so repeating the count a third place (banner → this popup's header) would recreate the exact "same signal, multiple mechanisms" problem §1 diagnosed. The flagged row itself still carries its warning icon inside the popup, same as on the card, so you can still find it — just not a second counter.
  2. No filter segmented control (All/Interest/Transfers). EPF's version needs one because a single FY can hold 12+ contribution rows plus occasional interest/transfer rows — filtering matters at that volume. PPF has at most a handful of rows per year (1–2 deposits, 1 interest), so a filter would be UI for a problem PPF doesn't have. If PPF ever grows multiple withdrawals/transfers per year this is easy to add back using the same `SegmentedControl` EPF already uses.

New per-FY progress bar (the one genuinely PPF-specific ask): every FY band gets its own "₹X / ₹1.5L" bar in the same visual language as the card's This-FY tile. The current, still-open FY (2026-27 above) keeps the tile's blue "in progress" / green "full" coloring, since it's still actionable — you can still deposit before the year closes. Past, closed FYs (2025-26, 2024-25) render the same bar in a muted slate fill instead — they're historical record, not something to act on, so they intentionally don't borrow the actionable blue/green language that could wrongly suggest there's still something to do about last year's deposits. A fully-maxed closed year gets a small "✓" next to its total, mirroring the card tile's own "✓ Full" treatment, so "this year was maxed out" reads the same way everywhere it appears.

4New — educational info icons + the Withdrawal tile
Rounds 2+3, additive to the already-approved design above — nothing in §0–§3 changes. Three verified PPF facts the user wants surfaced (5th-of-month interest timing, the ₹500 minimum deposit/penalty, and partial-withdrawal eligibility) become two tappable ti-info-circle icons, each opening a small centered modal. Two icons, not three — the 5th-of-month rule and the minimum-deposit rule are merged into one "This FY" info icon, since both are about the SAME underlying question ("what do I need to know about depositing into this account this year?"). Round 3 revision: withdrawal rules no longer live on an icon bolted onto the Maturity tile — they get their own dedicated full-width Withdrawal tile below the two-up row instead (powered by the new ppfWithdrawalEligibility()), showing the actual eligibility state and, once eligible, the real withdrawable rupee amount — not just a fact-lookup icon. The "i" on it still opens the identical rules modal unchanged from round 2.

Retirement
This FY deposit rules✕
Interest timing
Deposit on or before the 5th of a month and it starts earning interest that same month. After the 5th, it only starts earning from the following month.
e.g. deposit on 3 Aug → earns interest from August.
Deposit on 15 Aug → earns interest only from September.
Minimum & penalties
PPF needs at least ₹500 deposited every financial year to stay active. Miss a year and the account goes inactive — no deposits or loans against it until revived.
Reviving costs a ₹50 penalty + ₹500 arrears per missed year. A 2-year gap = ₹100 penalty + ₹1,000 arrears = ₹1,100 to reactivate.

Why always-visible, not conditional on account age

The Withdrawal tile is always present, regardless of the account's age — a brand-new 1-year-old PPF still shows it (in its "not yet eligible" state), not hidden until a few years before eligibility. This call carries over unchanged from round 2's reasoning (then about an icon, now about the tile it lives on): considered and rejected hiding it, since conditionally showing/hiding this affordance based on account age teaches the wrong lesson — it would imply the RULE itself doesn't exist yet for a young account, when it's a fixed fact about PPF that's genuinely useful to know early. The tile's own "not yet eligible" state plus the "i" already handle "is this relevant to me right now" without hiding the fact itself — and unlike a pure fact icon, the tile ALSO surfaces something an icon-only design couldn't: eligibleFromFy, a concrete "come back in FY 2029-30" date, right on the card, with no tap required.

Icon color deliberately never inherits the tile's own state color (This-FY's blue/green, Withdrawal's teal, Maturity's purple) — every info icon renders in the same neutral slate (--text3/theme.textTertiary) regardless of which tile it sits on or that tile's own current color, so "this is general reference material" reads as one consistent visual language, distinct from the tile's own live, account-specific state.

Masking: the Withdrawal tile's amount masks the same way the This-FY tile's does — the digits swap to •••• while the static " available" suffix stays visible (data-real/data-mask above mirror the app's own real convention of masking only the number, never the surrounding label). The "not yet eligible" state has no rupee amount to mask at all — an FY label reveals nothing sensitive.

Notes for the build step (not part of this proposal's approval)

No app-code changes have been made. This is a mockup-only proposal per docs/DESIGN_GUIDELINES.md §6 / CLAUDE.md's design workflow.

Data this reuses as-is, unchanged: ppfBuildCardData (maturity/FY figures), findMissingPpfInterestFys (drives the chip list), findAllPpfReviewFlags (drives the review-count line and the row icon). No new calculation logic — purely a layout/grouping change to the same inputs the current card already reads.

Divergence from EPF's card, deliberate: EPF keeps Import/Export as their own top-of-card row because EPF genuinely has more going on below (Employment, hikes, monthly contribution, retirement projection) that the Import/Export pair sits above as a clear "utility strip." PPF has only one sub-section (Transactions), so folding Import into that section's own header — just recoloured neutral — avoids adding a whole extra row for a single button pair. The "one attention banner, chips for repeats" pattern proposed here for PPF is worth considering as a follow-up for EPF's own stacked missing-interest banners and "still working here?" prompts, which have the identical N-banners problem — flagged here, not solved here, since this task's scope is the PPF card only.

Open question for the approver: whether the missing-year chips should open the transaction sheet directly (today's behaviour, kept as the default assumption above) or a small inline list — a chip row already avoids the N-banner problem either way, so this is a minor follow-up decision, not a blocker.

New for §3's popup — core logic that doesn't exist yet: ppfThisYearDeposits() (packages/core/src/core/portfolio/ppfCalculations.ts) currently only computes deposits for the live financial year (it filters from ppfFyStart() onward). The per-FY bars in §3 need a generalized ppfDepositsForFy(transactions, fyStartYear) variant the popup can call once per FY group — same ₹1.5L ceiling, just parameterized by year instead of hardcoded to "now." This mockup shows the target UI only; that function doesn't need to exist for this proposal to be reviewed.

Preserved as-is: interest rows in the new popup are shown with their existing flag icon but are not tappable for a correction flow — matching ppfReviewFlags.ts's own doc comment that PPF has "no equivalent transaction-detail popup today; this is flag-only," unlike EPF's tappable interest breakdown. Making PPF's flagged rows correctable is a real follow-up, but out of scope here — introducing it quietly inside this popup would be scope creep past what was asked.

Round 2 addition (§4, this pass): two new "i" info icons + their modals, additive on top of the already-built §0–§3 design (which has since shipped to apps/mobile) — nothing above this note was re-opened or changed. All three facts they surface (5th-of-month interest timing, ₹500 minimum deposit/₹50 penalty per defaulted year + arrears, and partial-withdrawal eligibility/cap) are verified PPF rules supplied directly by the requester, not invented or guessed. No new calculation logic needed for the withdrawal modal's personalization — it reads the already-computed ppfData.yearsElapsed, just formats a sentence from it (≥ 6 → "eligible now", else "eligible from year 7 (~N more years)" where N = Math.ceil(6 - yearsElapsed)). This establishes the app's first "i" info-icon → centered small-modal pattern (no tooltip/popover component existed anywhere before this) — worth reusing verbatim for any future "explain a rule, don't flag a problem" need elsewhere in the app, rather than each screen inventing its own variant.

Round 3 revision (this pass): the withdrawal-rules icon moves off the Maturity tile entirely onto its own new full-width Withdrawal tile below the two-up row, now backed by a real, already-built-and-tested core function — ppfWithdrawalEligibility(txns, ppfOpeningDate): PpfWithdrawalEligibility | null (packages/core/src/core/portfolio/ppfCalculations.ts) — returning { eligible, eligibleFromFy, maxWithdrawable }, null only when the opening date is unknown at all. This is a genuine capability upgrade, not just a relayout: round 2's icon could only ever explain the RULE; this tile now also shows the real computed rupee amount once eligible, and a concrete "come back in FY 2029-30" date before that — both come from the same function, so the tile and its "i" modal can never disagree about eligibility. The modal's own content/copy is untouched from round 2, byte-for-byte — only its entry point changed. The This-FY tile's "i" (interest timing + minimum/penalty) is completely unaffected by this revision.
