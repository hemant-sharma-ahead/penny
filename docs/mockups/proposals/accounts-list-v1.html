Accounts list — decluttering the row

Grounded in the real AccountList.tsx/AccountsPage.tsx on apps/mobile. Each row currently carries: icon tile, name (1 line, truncates), type subtitle, balance (+ "in net worth" caption), a chevron ("view transactions"), and up to three more icon buttons — Import (bank/credit card only) or Reconcile (cash/wallet only), Edit, Delete — all permanently visible and fighting the name for horizontal space. That's why "HDFC Credit Card" truncates to "HDFC ..." even with visible slack in the row: the name's flex-1 column is what gets squeezed after chevron + up to 3 × 30px icon buttons + their gaps claim their share first.

Direction D — Wallet card carousel (chosen — primary Accounts view)
Revised per feedback: this is no longer a "clean card, hidden long-press" concept — it's the primary Accounts view, replacing the list entirely. Each account is a full-bleed hero card (own identity colour as gradient, balance-forward). Two changes from the last pass: (1) Import/Reconcile, Edit, Delete are now always-visible icons along the card's bottom edge — a full-width hero card has plenty of room, so this doesn't recreate the old list row's crowding; the big balance stays the undisputed focal point up top, actions are a quiet row below a soft divider. (2) Total Balance is pinned above the carousel (never something you swipe through to find), and the condensed all-accounts strip stays below so "see my whole net worth at a glance" survives even though only one card is on-screen at a time.

Direction D — Mini Cards v2 (per-account colour + real-card sheen)
Fixes what shipped: the live build coloured every card from acc.color with no glow at all, which is why "HDFC Bank" rendered flat and dull, and why two bank accounts would look near-identical unless the user manually hand-picked distinct colours. Here colour is drawn from a small curated set of jewel-tone gradients, assigned per account (deterministically, e.g. hashed off acc.id) — not per type — so two accounts of the same type land on genuinely different hues. The one clamp: cash/wallet accounts are always forced into a green-family subset of that same palette, regardless of the hash, so "green = cash" stays a reliable visual cue. Card "feel" also got richer: a diagonal light-sheen streak, a second darker glow low on the opposite corner for depth, a faint brushed-texture overlay, and an inset top highlight — evoking a real metal/plastic card without any literal chip/number skeuomorph.

Decision: Direction D (wallet card carousel), refined per feedback — this is the direction going to implementation. Two changes from the first pass: actions moved from a hidden long-press sheet to an always-visible icon row along each card's bottom edge (discoverability over the "no buttons at all" purity — a full-bleed card has the room, so this doesn't recreate the old list row's crowding), and the Total Balance card now sits pinned above the carousel with the condensed all-accounts strip still below it, so whole-net-worth scannability doesn't depend on swiping through cards one at a time.

For the record, the earlier comparison: A (swipe to reveal) was the safest incremental fix — it fully declutters the old list row by reusing SwipeableRow, the same component already shipped on the Transactions tab, at effectively zero new-pattern cost. B (kebab, refined) is the most universally discoverable action-affordance (a "⋮" needs no gesture literacy) but costs an extra tap per action and a new popover pattern. C (two-line) solves truncation with zero new interaction but doesn't actually reduce clutter, just spreads it over a taller row. D was chosen because it's the only option that changes the screen's whole personality rather than tidying the same row shape — worth the larger build (snap-scrolling carousel, per-account gradient theming, a condensed secondary list) for an Accounts screen that reads as distinctive rather than "another finance list."
Cross-platform note. apps/web-react's AccountList.tsx is frozen (2026-07-31) and was never updated with the Import button, the tap-to-view-transactions drill-down, or the chevron — it only ever shows Reconcile (cash/wallet) + Edit + Delete, no chevron. The two platforms already disagree, and that's expected: web is a historical reference only, not a target to mirror. This redesign is mobile-only; no web-react change is proposed or needed.

Aside (not part of this redesign, worth a separate look): the Total Balance card's caption reads "Across {accounts.length} accounts in net worth" using the full account count, but the total itself only sums accounts with includeInNetWorth true (e.g. a credit card can be excluded) — so the caption can overstate how many accounts actually feed the number above it. Flagging since it's adjacent to this screen, not fixing it here.

Grounding for this proposal

  • Real code read: apps/mobile/src/features/accounts/AccountList.tsx, AccountsPage.tsx (renders PaymentModesSection directly below — kept in every frame above so the redesign doesn't ignore it), useAccounts.ts, and packages/core/src/core/accounts/meta.ts for the real per-type icon/colour/label values used in the sample data above.
  • Existing pattern reused: apps/mobile/src/features/expenses/transactions/SwipeableRow.tsx — already built on react-native-gesture-handler's ReanimatedSwipeable, already wired into TransactionsTab.tsx. Direction A proposes reusing it, not inventing a new one.
  • Research: Material Design's own card guidance recommends an overflow menu once a card has more than two supplemental actions (informing Direction B); Apple Wallet / Google Pay's swipeable card-stack pattern (tap a card for detail, long-press/drag for management) informed Direction D's balance-forward hero carousel and long-press action sheet; CRED's dark-mode-first, high-contrast list rows and INDmoney's dense multi-account aggregation view were both used as reference points for keeping the balance/subtitle typography calm rather than decorative.
