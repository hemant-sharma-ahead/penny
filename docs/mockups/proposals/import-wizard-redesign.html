Import Expenses — redesign directions

Three genuinely different visual directions for Resolve (categories + accounts) and Preview, grounded in the real apps/web-react/src/features/import/ screens and a realistic Cashew/MoneyView-scale file (69 rows read, 61 ready, 8 needing attention). Switch between directions with the tabs below — this file is a comparison artifact, not a single final design.

What's broken today: Resolve shows a flat list of dropdown-only cards for every distinct source category/account with no visual hierarchy or grouping cues. Preview's "Needs attention" cards show only "Row 3: Missing or unrecognised date" above three empty inputs — the user has no way to see what the source file actually contained for that row, so there's nothing to go on when filling the blanks. And the wizard is 5 rigid steps when categories, accounts and preview are really one decision session.
Preserves today's step-by-step shape

A · Wizard, Polished

Same 5-step flow (Upload → Map columns → Resolve → Preview → Done) — but Resolve gets a segmented Categories/Accounts switcher with compact suggestion pills instead of bare dropdowns, and every "needs attention" row in Preview now shows the actual raw source columns read-only above the fixable fields, so the user can see what to type.

Most novel — one decision at a time

C · Guided Card Stack

Instead of a list of 12 category cards or 3 account cards at once, each distinct category/account is its own swipeable card in a stack — one decision fully in focus, a recommended action pre-highlighted, tap to accept or override, then the next card slides up. Ends in the same Preview as Direction A. Genuinely different rhythm from both other directions; higher risk (more taps for power users resolving many categories at once) but the friendliest "I don't know what to do" experience.

Recommendation

Ship the Preview raw-data-strip fix (complaint #2) regardless of direction — it's the clearest, lowest-risk win and the user's most concrete complaint. For the wizard-shape question:

  • Direction B (Single Review Screen) is my pick. It directly answers "hoping for a single screen" without losing clarity — collapsed/done sections keep it uncluttered per DESIGN_GUIDELINES.md's "uncluttered first," and the sticky progress bar keeps orientation that a flat merge of three pages would otherwise lose.
  • Direction A (Wizard, Polished) is the safer fallback if Direction B's collapsible-section pattern proves awkward on very long files (69 rows is easy; a 1,500-row bank statement export may make one continuous scroll feel heavier than three focused steps) — worth a quick gut-check against a larger sample file before committing.
  • Direction C (Guided Card Stack) is the weakest fit for Penny's actual usage: a file with 12 categories means 12 forced sequential taps before seeing anything else, which cuts against "uncluttered first" more than it helps — I'd park it unless user testing specifically shows people are lost by seeing all 12 at once.

Verdict: build Direction B for real, keep Direction A's raw-data-strip Preview component as the shared building block either way, drop Direction C.

Cross-platform note: apps/mobile/src/features/import/ImportPage.tsx is currently stale relative to this rewrite — it has no Resolve step, no Map Columns step, and its useImport() shape (toImport/unrecognisedCount) doesn't match the new core (readyRows/rejectedRows/categoryResolutions/ accountResolutions). Whichever direction is approved, mobile needs a full port of the new import flow, not just a style pass — worth flagging in docs/MOBILE_PARITY.md as its own follow-up once the web design is locked.
