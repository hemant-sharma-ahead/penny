SMS Parser Verifier — v2, light + scale-first (click through it)

This one is a working prototype, not a static picture — click banks, click "Test", click table rows, click pages. It's pre-loaded with 2,400 synthetic fake results so pagination/search/filtering are genuinely testable, not just implied.

What changed from the last version, directly from your feedback:
1. Light theme, not dark.
2. Layout flipped: a right-hand reference panel shows each template as a read-only "paper" card (regex + sample, nothing to edit inline) — the whole middle column is now just testing input + the results table, no competing sections.
3. Editing or adding a template opens a popup (same modal pattern as Export/Import) instead of taking over card space inline.
4. The actual scale problem: the table is paginated (100/page here), there's a search box to filter by sender/message text, a big stat-card summary strip up top, and a progress bar for the parse itself — try pasting a large batch below and watch it, instead of the whole table just freezing or dumping 10,000 rows into the DOM at once.

Why this actually solves the 5,000–10,000-message problem

  • Rendering is capped, data isn't. Only the current page's rows (100 by default) ever touch the DOM — pasting 10,000 messages parses all 10,000, but the table never tries to render more than a page at a time. This is the same "first N + show all" render-cap principle already codified in docs/ARCHITECTURE.md for bulk-import screens elsewhere in the app, applied here.
  • Parsing itself is chunked, with a real progress bar — instead of one long synchronous loop that can visibly freeze the page for several seconds on a slow machine, the parse runs in batches (e.g. 500 at a time via requestAnimationFrame), yielding back to the browser between batches so the tab stays responsive and you can literally watch it counting up.
  • Search + stat cards** make 10,000 results scannable — the four big stat cards up top are both a summary AND a filter (click "❌ Unrecognized" to jump straight to just those 138), and the search box narrows by sender or message substring on top of that filter — so "show me every unrecognized message from senders containing 'PSG'" is two clicks + a few keystrokes, not scrolling through thousands of rows.
  • Copy actions operate on the full filtered set, not just the visible page — pagination only limits what's drawn on screen; "Copy (redacted)" still exports every matching row regardless of which page you're looking at, since building a text string is cheap even at thousands of rows (only DOM rendering is the expensive part).
  • Right panel is reference-only — every configured template for the selected bank, always visible while you work in the middle column, no clicking back and forth between "browse" and "test." Editing opens a popup so it never disturbs this panel's layout or the middle column's space.
