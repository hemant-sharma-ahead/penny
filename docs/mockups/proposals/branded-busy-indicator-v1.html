Branded busy/loading indicator — Penny logo mark

A new shared components/ui/ component (working name PennyLoader) meant to slot into Button.tsx's existing loading prop (replacing the generic white ActivityIndicator) and to stand alone as a full-area busy state anywhere a noticeable-but- bounded delay happens (initial sync, PDF/CSV parsing, an AI request to Chip, etc.) — not built one-off for any single screen. All three treatments below reuse the same coin medallion (gold radial gradient + sprout, the circular core of PennyLogo/PennyWordmark), shown at the button's current small size and at a larger standalone size, on both Light and Dark. Colours here are the real token hex values from packages/core/src/theme/tokens.ts for demonstration only — the real component takes them from useThemeColors(), never hardcoded.

There is also no standalone/full-area busy treatment today — screens that need one currently improvise (a plain spinner + text, unbranded), which is the gap this proposal closes.

2 — Pulse / breathing

The medallion stays upright (no rotation) and gently scales + fades in and out, like a heartbeat/breathing motion. Calmer and quieter than a spin — fits Penny's "calm, glanceable" ethos particularly well for a full-screen busy state someone stares at for a couple of seconds, though at small inline-button size the motion is subtle enough it can read as "is this even loading?" at a glance.

3 — Partial-ring sweep

The coin stays still; a short bright-green arc (--color-primary, not gold — see judgment call below) traces around its edge like an indeterminate circular progress ring, continuously chasing itself. Closest in spirit to a conventional "loading ring" (most legible as "working" at a glance, arguably the most universally-recognised shape of the three) while still being visibly Penny's coin at the centre, not a bare ring. Costs the most to implement faithfully on RN (see judgment call below).

Notes & judgment calls

  • The medallion is the coin core only, not the full square PennyLogo. The full logo is a rounded-square icon with an asymmetric horizon/sky scene behind the coin (dawn gradient, ground strip) — spinning that whole square reads oddly mid-rotation (the horizon tilts through nonsensical angles). The coin medallion itself (gold radial gradient circle + sprout + thin ring, the same element PennyWordmark already uses standalone) is inherently circular and reads cleanly at any rotation angle, so all three treatments adapt that piece, not the literal app icon. Flagging this as a deliberate scope call, not an oversight.
  • Treatment 3's arc colour is --color-primary (green), not a gold-on-gold ring. A gold arc tracing a gold coin has very low self-contrast, especially on Light's near-white stage background; green against gold is legible in both themes and doubles as a small brand-consistency cue (green is Penny's one fixed accent across every theme). Flagging as a judgment call — an alternative is a white/on-tint arc instead, but that reads correctly on Dark and gets lost on Light.
  • Timing is a judgment call, not measured against a real device yet: rotate at 1.1s/revolution (comparable to iOS's native spinner, ~1s), pulse at 1.7s per breath (slow enough to read as "calm," fast enough not to feel stalled), sweep arc at 1.3s/revolution. These are starting points for the real Animated/reanimated implementation to tune, not settled values.
  • Recommendation: Treatment 1 (rotate) as the default for both the Button loading slot and general standalone use — it's the cheapest to build correctly (no masking/arc math), least likely to look broken on a slow/first-gen Android device (a plain rotation degrades gracefully; an animated conic/arc sweep is more sensitive to dropped frames), and needs no extra judgment call about arc colour contrast. Reserve Treatment 3 (sweep) for a specific screen that wants a more "progress-y" feel — it's the most technically expensive to implement well (RN has no conic-gradient; the arc must be a react-native-svg <Path> with an animated strokeDashoffset, per docs/DESIGN_GUIDELINES.md's cross-platform "platform-appropriate translation" principle) and is the one treatment with a real risk of the arc's start/end caps looking slightly jittery on lower-end hardware. Treatment 2 (pulse) is a fine alternative for a single calm full-screen state (e.g. an initial app-open sync) but reads too subtle at the small inline-button size to be the universal default.
Recommendation: ship Treatment 1 (rotate) as PennyLoader's only mode for v1 — a single well-executed default beats three competing "spinner styles" scattered across the app (this same "one capability, one control" instinct that governs consolidating duplicated controls also argues against giving every screen author a style dial with no clear standard). If a specific screen later makes a strong case for the sweep or pulse treatment, add it as an explicit variant prop rather than picking ad hoc per call site.
Cross-platform scope: apps/web-react is frozen (no feature/design changes per CLAUDE.md) — this component is proposed for apps/mobile only. That's not a parity gap needing reconciliation, just this task's natural scope: the legacy web app keeps its existing (also-generic) spinner treatment unchanged and un-mirrored.
